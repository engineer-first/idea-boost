# 共有成果の保存と閲覧権限

通常開発・検証・本番は同じ RoomDO の保全、再試行、30日の期限判定を使います。保存先は環境ごとに分離され、全ルームの成果一覧・詳細は Google または開発用アカウントでログインした、`shared_outcomes:read` を持つユーザーだけが `/shared-outcomes` から閲覧できます。Worker は取得のたびにセッションと D1 の現在の権限を確認します。

| 環境     | 起動・保存先                                                       | 初期権限                                                                       |
| -------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 通常開発 | `npm run dev` と `npm run dev:api`。通常の Wrangler ローカル保存先 | 開発用ログイン時、`DEV_USERS[0]` の Owner に read と manage\_access を自動登録 |
| 検証     | `npm run dev:verify`。`.wrangler/verification/state`               | 同じ Owner に自動登録                                                          |
| 本番     | 本番 Worker・D1・RoomDO                                            | 運用 CLI で既存ユーザーに明示的に登録                                          |

`npm run dev` だけでは Next.js のみ起動します。通常開発の D1 migration は `dev:api` 起動時に適用されます。検証環境は専用 D1 に migration を適用します。

## 本番の初期権限

[認証と権限付与](access.md)に従い、閲覧担当に`shared_outcomes:read`、閲覧者を管理する担当に`shared_outcomes:manage_access`を付与する。

## 閲覧者の管理

`shared_outcomes:manage_access` を持つユーザーは `/admin/access` で登録済みユーザーに read 権限を付与・剥奪できます。対象ユーザーは事前に Google ログインを済ませてください。この画面と API から manage\_access 自体を変更することはできません。Worker が操作のたびに管理権限を確認します。

## 成果を探す・見比べる

`/shared-outcomes`でルーム名・表示用ID・内部のルームIDの一部を検索し、記録（途中／確定）、到達フェーズ、保存状態を組み合わせて絞り込めます。本文や付箋は検索対象ではありません。「条件をクリア」で一覧へ戻せます。表示件数は取得済みの成果の数で、続きがある場合は「次の成果を表示」で追加します。一致する成果がまだなくても、続きが残っていることを表示します。

一覧は最終利用の新しい順に並び、閲覧期限と保存状態を比較できます。詳細の「前の成果」「次の成果」は取得済みの一覧内で移動します。ブラウザの戻る・進むと「成果一覧へ戻る」は、検索条件、追加済みの一覧、スクロール位置を保ちます。戻る際にも現在の権限で再取得します。

「リンクをコピー」で詳細のURLを共有できます。検索・絞り込み条件もURLに残り、未ログインの場合はログイン後に元の詳細へ戻ります。受け取った人にも閲覧権限が必要です。通信失敗時は「再試行」で同じ取得をやり直し、追加取得の失敗では表示済みの一覧を失いません。

## 保存状態と失敗時の対応

共有成果はRoomDOで保全し、D1の成果専用投影へ非同期で反映する。ルーム作成と成果の初期索引は同じD1 batchで作り、本文の反映と索引の更新はバックグラウンドで行う。D1のルーム一覧には共有本文を含めない。完了時はその時点の盤面を固定し、後からボードに戻っても書き換えない。共有から個人用へ戻した付箋は次の途中記録から除外する。

反映に失敗した場合は保全した記録で自動再試行する。閲覧側は前回の成功分と保存失敗を示し、一般ユーザーへ追加操作を求めない。未完了ルームは作成・最後の利用から30日。本人向け再訪の対象となる完了ルームは初回完了から30日の固定期限とし、閲覧・退出・再試行では延長しない。期限後は閲覧を止めて削除し、削除失敗はWorkerログの `shared-outcome-expiry-delete-failed` で検知する。投影失敗は `shared-outcome-projection-failed`。ログには秘密値や共有本文を出さない。

既存ルームは通常アクセス・成果一覧取得時に成果の保全を初期化する。導入前の最後の共有操作時刻は記録されていないため、旧ルームの作成日時を期限の起点にし、初回閲覧によって期間を延ばさない。導入前の削除済みルームや未保存の編集履歴は復元できない。デプロイ前にD1 migrationを適用する。

## 進行記録を確認する

`/shared-outcomes`のルーム詳細から「進行の記録」を開く。訪問順の開始・終了・経過時間を確認し、「盤面を見る」で当時の配置と全文を読む。フェーズを切り替えられ、本文は選択した記録だけ取得する。

正常な空盤面、反映待ち、反映失敗・再試行中、盤面なし・復元不可、取得エラーは別の状態。反映失敗や取得エラーでは「最新の状態を取得」で再取得する。後の盤面で欠落を埋めない。閲覧のために作業用ルームへ接続する必要はない。

経過時間は休憩・会話・切断中を含む。迷いや不具合とは断定せず、開始時刻不明・終了未記録は推測しない。導入前の履歴は復元できない。

記録する内容・除外する個人情報・完了参加者の再訪・保持期限の要求は[進行仕様](../product/sprint-flow.md#共通の振る舞い)、保全と投影の構成は[構成概要](../architecture/overview.md)。検証の準備とやり直しは[ローカル検証](../development/local-verification.md)を参照する。Storybookとモックは見た目の確認用で、永続化・認可・再試行・期限の保証には使わない。
