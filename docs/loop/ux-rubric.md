# 巡回の旅と重大度

patrol が歩く利用者の旅と、所見の重大度。人物と要求の正本は [PRD](../prd.md)・[進行仕様](../product/sprint-flow.md)、呼び方は [用語集](../glossary.md)、見た目は [DESIGN.md](../../DESIGN.md)。
ここには「どこを歩き、何を所見にするか」だけを置く。

## 歩く人と画面

- 人物：アイデア出しに慣れていない学生チーム（PRD のメインペルソナ）。進行役がいなくても、画面だけで次にやることが分かるかを見る。
- 人数：3人（開発用ユーザー1人＋別のブラウザ context のゲスト2人）。1人では共有・発表者交代・投票の旅を歩けない。
- 画面：PC（1280×800）と iPad 横（1180×820）で全部の旅。スマホ縦（390×844）は J0・J1 の入口だけ（専用 UI ができるまで）。

## 旅

| 旅 | 歩く範囲                                                                          | 合格の目安                                                 | 台帳     |
| -- | --------------------------------------------------------------------------------- | ---------------------------------------------------------- | -------- |
| J0 | トップ → はじめる（Google / ゲスト、表示名）→ ホーム                              | 説明を読まずにホームまで来られる                           | C01      |
| J1 | ルーム作成 → 招待URLで2人・3人目が参加 → 開始待ちの画面で顔を変える → 開始        | 招待の渡し方と開始の仕方が画面で分かる                     | C02      |
| J2 | 課題整理：マイ付箋とタイマー → 共有（発表者交代・パス）→ グループ化 → 投票 → 決定 | 各ステップで「今なにをするか」と「次へ進む条件」が分かる   | C03〜C06 |
| J3 | 問いの整理：HMW の入力 → 共有 → 投票 → 決定                                       | 問いの書き方の例が手元で読め、決めた問いが次へ引き継がれる | C07      |
| J4 | アイデア決定：発想支援を開く → 2軸マップ → 投票 → 採用                            | 発想支援が作業を隠さず、採用案が1つに決まる                | C08      |
| J5 | 完了 → 成果のコピー・テキスト保存・PNG 保存 → ホームから再訪                      | 決まった3項目を持ち帰れ、後日開き直せる                    | C09      |
| J6 | 途中のできごと：切断と再接続、退出、他の参加者の除外、別ルームへの移動            | 進行が止まらず、本人と他の人に何が起きたか分かる           | C10      |

タイマーは待たずに進める：開発用の短い時間設定か、全員の「できた！」で進む。

## 重大度

| 重大度 | 意味                                                                                     | Issue                                                                   |
| ------ | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| S1     | 旅が最後まで進めない。未共有の付箋・投票中の個別票が他の人に見える。データが消える       | `loop:ux` `P0`                                                          |
| S2     | 迷って止まる、誤操作から戻れない、PC・iPad で崩れて操作できない、axe の critical/serious | `loop:ux`                                                               |
| S3     | 進めるが分かりにくい・文言や見た目の好み                                                 | Issue にしない。patrol log に一覧だけ（人がまとめて残す・消すを決める） |

合否は「旅が最後まで行けたか」と「S1/S2 があるか」で決め、点数で丸めない。

## 所見の書き方

- S1/S2 は 1所見＝1 Issue（1回3件まで）。Type は `Bug`（壊れている）か `Task`（分かりにくい）。本文は [Issue記述ルール](../team/issue-writing.md) の Why と現状。Project の状態は `着手可能` にする。
- 現状に、旅・画面幅・再現手順・スクリーンショット（ローカルの架空データだけ）を置く。「なんとなく良くない」は所見にしない。
- 進行仕様と食い違うときは、どちらが正しいかを決めず、食い違いとして書く（仕様の判断は人）。
- 重複は `gh issue list --label loop:ux --state all --search "<語>"` で探し、既存へ「<SHA> で再現」とコメントする。

## 較正の記録

人が採点し直してずれた観点を、日付と1行で足す。
