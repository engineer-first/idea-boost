# ADR 0035: ループは人にしかできない作業だけを人に頼み、頼んだことを確実に届ける

## Context

ADR 0031 は、ループが課金・契約、ruleset・secret・environment・認証方式の変更、学外への連絡を行わず、`needs-human` に止まった場所を書くと決めた。2026-11-27 に確かめると、この中には人の本人確認や支払いが本当に要るものと、決まりで止めているだけのものが混ざっていた。ループが使うオーナーの GitHub アカウントは repository の admin で、Actions variables は AI が設定できた。secret も、値さえあれば登録できる。足りないのは秘密の値で、登録の操作ではない。

もう1つの問題は、頼んだことが届かないこと。ループはオーナーの GitHub アカウントで動くため、`needs-human` を付けても GitHub はオーナー本人に通知しない。オーナーが気づく経路は定時のまとめだけだった。同日オーナーは、人による詰まりはできるだけなくし、できない場合はきちんと人に助けを求めるよう求めた。

## Decision

ループが人に頼むのは、人の本人確認・支払い・判断が要る作業だけにする。人が値を用意すれば AI が登録できる作業は、ループが行う。

- 人に残すもの：課金・契約、ruleset・environment・認証方式の変更、secret とトークンの値の発行、学外への連絡（公開アカウントでの投稿を含む）。
- ループが行うもの：公開してよい値の Actions variables、オーナーが決めた置き場に値を置いた repository secret の登録と、ループ自身が使う秘密の読み出し、所有確認のための DNS の TXT レコードの追加、手順が運用文書にある外部サービスの設定。値は表示も保存もしない。

秘密の置き場は、オーナーが値を作った手元の端末から保存するだけでループの動く端末に届く、共有の保管庫にする。値を端末の間で運ぶ作業を人に残さないため。

人に頼むときは、止まった場所・してほしいこと・それを用意すれば次から AI ができるかを書く。頼んだことは、GitHub の通知に頼らず、Discord でオーナーを直接メンションして届ける。

### 本ADRで決定しないこと

secret の置き場の名前、登録の手順、通知のチャンネルと文面、人に頼む作業の一覧は、ループ開発の文書と通知の workflow へ委譲する。

## Consequences

- 良い影響：トークンを作り直したときなど、人の作業が「手元で保管庫に保存する」だけになる。登録・反映の確認はループが行う。
- 良い影響：`needs-human` がその場でオーナーに届く。定時のまとめを待たずに済む。
- 悪い影響：ループが repository secret を書き換えられるようになる。間違った名前に登録すると、次の公開や CI が壊れうる。登録の記録を PR か Issue に残し、壊れたら mend が直す。
- 悪い影響：保管庫を読むサービスアカウントのトークンが漏れると、保管庫の秘密がすべて読まれる。保管庫は自動化用に分け、人が普段使う秘密を置かない。
- 悪い影響：Discord の webhook やチャンネルが止まると、頼みごとが再び届かなくなる。workflow は送れなかったときに失敗として残る。
- 中立：`needs-human` の付け方・外し方と、R3 に残る作業を人が行う点は ADR 0031 から変わらない。
- 判断の出どころ：人の作業を AI ができるようにすることと、届かないときにきちんと頼むことは、オーナーが 2026-11-27 に求めた。線引きと Discord での通知は AI の提案。
- 見直す条件：ループが secret の登録で本番や CI を壊したとき。Discord 以外にオーナーへ確実に届く経路ができたとき。

## Alternatives Considered

- ADR 0031 のまま secret をすべて人が登録する案：値を作った人が、そのままブラウザで登録する手間が残り、登録漏れの確認もできない。採らない。
- ループにトークンを発行できる権限（Cloudflare の API Tokens の編集など）を渡す案：漏れたときの被害が大きすぎる。値の発行は人に残す。
- 秘密をループの動く端末のキーチェーンに置く案：最初はこの形にしたが、別の端末で作った値を運ぶ手間が残った。移行期間の予備としてだけ読む。
- 通知を Issue のアサインで代える案：今のアサイン通知は「着手します」と出るので、頼みごとと区別できない。

## Related ADRs

- ADR 0031：ループで改善から公開までを回す判断。ループが行わない作業の範囲をこの ADR で狭め、頼み方を足す。それ以外の判断は残る。
