# ADR 0027: 色と角丸はDESIGN.mdの名前で書き、色の直書きはBiome公式の2ルールだけで止める

## Context

DESIGN.mdのYAMLで色と角丸の値と役割を決めたが、画面が使うCSS変数（`app/globals.css`）はshadcn/uiの既定の値のままだった。どちらを正本にするかを決めないと、同じ値を2か所で保つことになる。

画面には、Tailwindの既定パレット（`bg-blue-500` など）やhex（`#RRGGBB`）を直接書いた箇所（以下、直書き）が35ファイル・約260件あった（2026-11-05の実測）。機能ごとに近い色をその場で選んでおり、付箋の「決定」を示す色が3つの値に分かれていた。DESIGN.mdの値を変えても取り残される部品が出る。一方で、テストやstoriesの見本の色、LPの配色の定義元、ガイドのイラスト、付箋の作者色の定義元のように、正当な直書きもある。一律に禁止すると開発の手間が増える。

同じ実測で、直書きは4つの形に分かれていた。既定パレットのクラス108件、CSSのhex 85件、tsx・tsのhex 64件、`bg-[#…]` のような任意値2件である。Biome 2.5.15の公式ルールで検出できるのは前の2つだけだった（CSSのhexは `style/noHexColors`、既定パレットは `nursery/noTailwindRawColors`）。後の2つは、リポジトリで既に使っているast-grepの自作ルールなら検出できた。`noTailwindRawColors` は試験段階（nursery）のルールで、`class` / `className` 属性と `cn()` などの引数だけを見るため、定数の文字列に書いた既定パレットのクラスも検出しない。

## Decision

色と角丸の値の正本をDESIGN.mdのYAMLとし、CSS変数はそこから生成する。画面では値ではなく名前で書く。DESIGN.mdにない色が要るときは、先に役割の名前をDESIGN.mdに足す。

直書きの検出には、Biome公式の2ルールだけを使い、ast-grepなどのルールは自作しない。2ルールが見ない形（tsx・ts内のhex、任意値、定数の文字列に書いたクラス）は、レビューで確認する。検出漏れを受け入れる代わりに、保守する検査を設定だけにとどめ、緩く始める。

例外は、その場所に理由付きの抑制コメント（`biome-ignore`）を書くことを基本にする。Biomeは理由のない抑制コメントを受け付けないため、例外の理由がその場に残る。ファイル全体が例外のときだけ `biome.json` の `overrides` に入れる。

CIでは2ルールをerrorで検査し、新しい直書きをマージ前に止める。

### 本ADRで決定しないこと

色と角丸の名前・値・役割と、淡い面の作り方（混色の色空間を含む）は[DESIGN.md](../../DESIGN.md)へ委譲する。`overrides` の対象ファイルとその理由は[biome.json](../../biome.json)とDESIGN.mdの「値を直接書かない」節へ委譲する。CSS変数の生成と検査のコマンドは[package.json](../../package.json)へ委譲する。角丸の直書きを検査するかは、この判断では扱わない。

## Consequences

- 良い影響：DESIGN.mdの値を変えると、生成したCSS変数を通じて画面に反映される。検査の保守は `biome.json` の設定だけで済み、検出の仕組みは上流が保守する。
- 悪い影響（受け入れるリスク）：検査の外の形は保証しない。定数の文字列は、ドット投票のシールの色で実際に死角になった。検査の外にある正当な直書き（作者色の定義元など）は抑制コメントが要らないため、理由がその場に残らない。
- 悪い影響：`overrides` に入れたファイルでは、例外の理由と関係のない直書きも検査を通る。
- 悪い影響：試験段階のルールに依存する。Biome 2.5.15の `noTailwindRawColors` は、`has-[[data-x]]:` のように角括弧が二重になるクラスを解析できず、設定の強さに関係なく解析エラーで終了コード1を返す。実装ではこの書き方を含むファイルの既定パレットの検査を `overrides` で外しており、そのファイルはレビューに頼る。この除外はAIの実装判断で、オーナーの個別の承認は記録にない。
- 中立：DESIGN.mdにない色が要るときは、先に役割の名前を足す手順が増える。
- 見直す条件：
  - `noTailwindRawColors` が安定版に入る、または名前・対象が変わるとき。
  - Biomeが二重の角括弧を解析できるようになったとき、または除外したファイルが二重の角括弧を使わなくなったとき。上流の追跡先を特定できていないため、Biomeを更新するたびに確かめる。
  - 検査の外の形や角丸から直書きが繰り返し入るとき。ast-grepで補う案を再検討する。

## Alternatives Considered

AIが示した候補と代償（以下は比較資料の記載）から、オーナーが選んだ。選んだときに、不採用の理由は記入されていない。

- 検査の道具：Biomeの2ルールを主にし、tsx・tsのhexと任意値だけast-grepで補う案（AIの推奨）。4つの形を検査できるが、道具が2つになり、nurseryへの追従も残る。当時数えた正当な直書き58件はすべてtsx・tsのhexで、ast-grep側では抑制の理由を強制できない。ast-grepにすべて寄せる案は、nurseryに左右されないが、検出の仕組みを自前で保守し、抑制の理由も強制できない。後に定数の文字列の死角が見つかり、検出するast-grepルールを試作して方針を広げる案もAIが推奨したが、オーナーは外してレビューに戻す方を選んだ。
- 例外の書き方：ファイル単位の例外だけにする案は、ファイル内のほかの直書きも通る。抑制コメントだけにする案は、イラストや色の定義元にコメントが並ぶ。
- CIへの入れ方：オーナーはinfoで入れて件数が減ってからerrorに上げる案を選んだ。足りない色の名前を先に足してからerrorにする案は、CIに入るのが最も遅い。既存の違反ファイルを例外に入れて最初からerrorにする案は、例外が35ファイルで始まる。
- 値の正本：`app/globals.css` を正本にし、DESIGN.mdを写しとして一致を検査する案。
