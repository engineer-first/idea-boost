# ADR 0031: 完成台帳を置き、エージェントのループを巡回から始める

## Context

開発の大半はAIエージェントが行うが、エージェントは人が起動したときだけ動く。作ったセッション自身が動作を確かめるため確認が甘くなりやすく、画面の崩れや迷う場所は、誰かが思い立って歩くまで見つからない。

PRDと進行仕様は詳しい一方、「いま何が確かに動き、何が足りないか」を1か所で読めない。完成の判断はIssueとPBIに散らばっている。

オーナーが個人で開発する別のリポジトリでは、2026-11-21から、完成台帳と役割ごとのループでエージェントが自律的に開発し、developへマージしている。IdeaBoostは5人前後のチームが開発する公開リポジトリで、developのRulesetsは承認を求めず、ループが動くオーナーのアカウントはadminである。そのままマージまで任せると、ループの誤りやIssueに書かれた指示の注入を技術的に止められない。

## Decision

PRDのうち「壊れていたら困る」振る舞いと、その確かめ方を、機械可読の完成台帳に置く。台帳の受け入れ条件を変えるのは人とし、状態を確かめて更新するのは人が起動するPRとする。作業者が条件を緩めて完了にする抜け道を塞ぐためである。

エージェントのループは、巡回だけから始める。巡回は1日1回、前回から画面か境界のコードが変わったときだけ、作った周回とは別のcontextでローカルの画面を歩き、重大な所見をIssueにする。コードを書かず、PRを作らず、マージしない。会話の記憶に頼らず、状態はGitHubとリポジトリに置く。

巡回の所見は通常のIssueとして `未整理` に入り、チームのトリアージに乗せる。読む量を抑えるため、新規は1回3件までとし、読まれていない所見が5件あるときは巡回しない。チームの誰でも、ラベル1つでループを止められる。

コードを書くループ（修理・完成・取り込みなど）とエージェントがマージする範囲は、巡回の結果を見てから別のADRで決める。

### 本ADRで決定しないこと

巡回の起動条件・上限・ラベル・止め方はループ開発の文書と判定スクリプトへ、各周回の手順は指示書へ、台帳の項目と受け入れ条件は台帳へ、旅と重大度は巡回の基準へ委譲する。委譲先へのリンクはReferencesに置く。

## Consequences

- 良い影響：人が起動しなくても、変更のあった日に画面が歩かれ、作った人とは別の目で所見が出る。完成までの距離が台帳のpass数で読める。
- 悪い影響：所見のIssueがチームのトリアージに加わる。上限（1回3件、たまったら止まる）で抑える。
- 悪い影響：エージェントの利用料が巡回1回ごとにかかる。Orcaは周回ごとにworktreeを作り、依存の導入で約1.7GBを使うため、オーナーが定期的に片付ける。
- 中立：ループを止めても、GitHubに残るのはラベルとIssueだけで、人の運用はそのまま続く。
- 保証しない範囲：巡回はローカルのPC幅だけを歩き、本番・iPad・スマホは歩かない。巡回の合格は、初学者チームが迷わず決められることの証拠ではない。
- 根拠未確認：台帳の項目の選び方と、巡回から始める構成はAIの提案で、オーナーとチームの採用を確認していない。
- 見直す条件：
  - 2週間の試行で、閉じた所見のうち完了で閉じた割合が半分を下回ったとき。巡回の基準を直すか止める。
  - 所見が5件たまって巡回が止まる日が続き、チームが所見を読まなくなったとき。
  - 次の段階（コードを書くループ）を提案するとき。

## Alternatives Considered

- 元にした個人リポジトリと同じく、修理・完成・取り込み・巡回・庭仕事・再計画の6つのループを置き、エージェントがdevelopへマージする案：最初に設計したが、AIのレビューで、adminのアカウントで動く間は迂回マージや注入を止められないこと、変更ファイルによるマージ範囲の判定に抜け道（rename、指示を縛る文書、テストの削除）が残ること、マージしない段階では修理・再計画がほとんど価値を生まないことが指摘され、巡回だけから始めることにした。
- 台帳をPRDの完成の北極星にし、ループが差分を埋め続ける案：IdeaBoostではPRDの多くが実装済みで、台帳が確かめ直しで早く埋まり、その後はループが好みの改善を回し続けるため採用しなかった。
- 巡回の所見を `着手可能` で起票する案：Issue運用では新しいIssueは `未整理` から始まり、チームが優先順を決めるため、ループが状態を進めないことにした。

## Related ADRs

- ADR 0024：優先順はProjectの共通の手動順で決める。巡回の所見もこの順に乗る。
- ADR 0030：CIはリリース時の致命的な不具合を止める基準とする。巡回はCIの外で画面を確かめ、置き換えない。
