# 0019: 保存待ちの共有付箋移動をローカルで受け付ける

- 状態：提案
- 決定日：未確定
- 記録日：2026-10-18

## 背景

[0006](0006-move-transactions.md)は、途中位置を確定状態から分け、位置・分類・成功記録を一括保存し、安全にUndoできるようにした。開始ACKを待たずに本人の表示を動かす一方、commitの結果待ち中は次のドラッグを拒否していた。このため、短い移動を続けると通信の往復時間によって入力が無視される。

[0018](0018-websocket-message-order.md)で同じ接続の要求順を守っても、確定応答を待つ時間は残る。中間位置の配信間隔を短縮しても、次の入力を拒否する条件は解消しない。

## 候補と決定

次のドラッグは表示中の位置を起点に受け付け、固定対象・移動量・工程と対象の版を本人のメモリ内に保持する。本人の表示には未確定操作を重ねる。RoomDOへ送る操作は常に先頭の1件だけとし、成功receiptを受けてから次を送る。離し終わった操作はstartとcommit、掴んでいる操作はstartとpreviewを送る。

本人の先行操作で変わった版だけを後続へ引き継ぎ、掴んだ位置は変えない。確定batchと互換note通知を本人の保存として扱い、再描画前の入力も受信済みの最新状態を参照する。確定位置・分類・履歴は従来どおりRoomDOの結果から更新する。各ドラッグを独立した操作として残すため、Undoも1回ずつ戻せる。

先行操作の拒否・結果不明、対象の競合、切断・再同期、工程や盤面変更では未送信分を破棄する。Escape・blurも未送信分を破棄し、現在のgestureだけの取消では既に離した操作を保つ。送信済みcommitは取消や再送をせず結果照会を続ける。Undo/Redoおよび非共有化は移動の確定待ちと重ねない。

複数のstartを同時送信する方式は本人のlockと版の競合を作る。最後の位置だけへ集約する方式はドラッグ単位のUndoを失うため採らない。表示中の位置を確定状態へ書き込む方式もRoomDOの権威を崩すため採らない。

## 影響と見直す条件

短い連続操作の追従を通信応答から切り離せる。WS形式・認可・原子的保存・操作IDによる結果照会は維持し、ポーリングやpreview配信の頻度は変えない。

通信が遅い間は未送信操作がメモリ内に蓄積し、他者への反映とUndo可能になる時点は遅れる。ページを閉じたり接続が切れたりすると未送信分は失われ、自動再送しない。長時間の遅延下で蓄積が問題になる場合は、保存待ちの表示や入力上限を、操作単位のUndoをどう扱うかと合わせて検討する。
