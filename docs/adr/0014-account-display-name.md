# 0014: 認証名から独立した共通の表示名

- 状態：提案
- 決定日：2026-10-11
- 記録日：2026-10-11

## 背景

Googleプロフィール名を初参加・招待で共有すると、本人が選ぶ前に本名が見える。
利用者はホーム・ルーム内のどちらで変更しても、在籍中のルームと次の参加で同じ表示名を使いたい。
入力は任意で、完了した成果と保全済み履歴は当時の名前を残す。

## 候補と決定

共通の表示名はD1のユーザーに認証名と別で保存し、認証済みAPIで本人だけが変更する。
ルーム内の現在名と共有通知はRoomDOが持つ。D1の参加候補索引から本人のルームへ更新世代付きで通知し、RoomDOが在籍・完了・期限と新旧を判定する。

参加中の名前が変わらない方式とルーム別上書きは、利用者がどこで変えても反映する要求に合わないため採用しない。
認証ユーザーの操作で全ルームを走査する方式は、無関係なDOへの負荷を増幅するため採用しない。

## 影響と見直す条件

- 新しい表示名は15文字以内。旧上限で保存した表示名は読み取り・配信を保ち、本人の編集まで自動で短縮しない。
- 未設定時はGoogle名を初期値にせず、入力せずに進む場合もアカウント別の匿名名を保存する。
- 同名でもID・識別色・権限・付箋・票を変更しない。旧WSのルーム限定改名は拒否し、再読み込みを案内する。
- 共通保存と複数DOの更新は単一transactionにできない。途中失敗は保存済み共通名を保ち、画面で再保存・再取得を案内する。更新世代で遅れた旧通知を拒否する。
- 候補索引は在籍の権威にしない。作成・参加・認可済みの閲覧/接続で補完し、退出・完了した候補はRoomDOで無操作にし、ルーム削除時に索引も削除する。導入前のルームは毎時の定期処理で未索引32件ずつ補完し、アクセス時にも最新名へ追いつく。
- 既存の未選択Google名は未完了ルームの現在名・共有順から匿名化する。本人が選んだ旧ルーム名、完了成果、過去の履歴は保持する。過去記録の削除・匿名化は別要件とする。

本人が同時に参加するルームが増えて応答時間に影響する場合は、配送の非同期化と完了通知を検討する。
