# 0014: 認証名から独立した共通の表示名

- 状態：提案
- 決定日：2026-10-12
- 記録日：2026-10-12

## 背景

初期はGoogleプロフィール名を使い、名前を変えたい人だけが任意の表示名へ変更する。
利用者は本人が変更した名前を次のルームへ引き継ぎたい。ルーム内での変更は、そのルームにも即時反映する。
設定前の入力促進は不要。完了した成果と保全済み履歴は当時の名前を残す。

2026-10-12に依頼者とスコープを再確認した。初期はGoogle名を使い、入力促進は設けない。複数ルームの同時利用は主要な用途ではないため、他の在籍ルームへの即時配送は行わない。

## 候補と決定

共通の表示名はD1のユーザーに認証名と別で保存し、認証済みAPIで本人だけが変更する。
ルーム内の現在名と共有通知はRoomDOが持つ。ルーム内からの変更は、本人の設定を保存してから操作対象の1ルームだけへ更新番号付きで通知する。RoomDOが在籍・完了・期限と新旧を判定する。ホームからの変更は保存だけを行う。

ルーム別の設定だけを残す方式は、次のルームに名前を引き継げないため採用しない。全在籍ルームへの即時配送は、主要な利用場面に対して参加先の索引・移行処理を増やすため採用しない。

## 影響と見直す条件

- 新しい表示名は15文字以内。旧上限で保存した表示名は読み取り・配信を保ち、本人の編集まで自動で短縮しない。
- 表示名の上書きがなければGoogleプロフィール名を表示する。本人が変更した値を認証名に優先し、再ログインでも上書きしない。Googleの初期名は入力の15文字上限と独立して読み取る。
- 同名でもID・識別色・権限・付箋・票を変更しない。旧WSのルーム限定改名は拒否し、再読み込みを案内する。
- 共通保存と操作対象DOの更新は単一transactionにできない。途中失敗は保存済みの設定を保ち、画面で再保存・再取得を案内する。同じルームへの遅れた旧通知は更新番号で拒否する。
- 作成・参加・再参加で保存済み表示名を読み、明示設定があればそのルームに適用する。閲覧・WS再接続では名前を同期しない。参加ルーム索引と定期的な移行処理は設けない。
- 既存のGoogle名・本人が選んだ旧ルーム名・完了成果・過去の履歴は自動で書き換えない。初参加の匿名化は今回の対象外。

複数ルームの同時利用と全ルームへの即時反映が必要になった場合は、参加先管理と配送方式を別途検討する。
