# ADR 0025: ルームにホストを置かず、退出を本人だけの操作にする

## Context

ルームには作成者を初期値とするホストがあり、解散・ホスト移譲・参加者の除外・ボードからの招待をホストだけが行える。進行（開始・次へ・完了）は既に全員の操作になったため、残るホスト権限はルームの存在と管理に関わる操作だけになった。

この差がユーザーの判断を増やしている。ホストは途中で退出できず解散か移譲を選ぶ必要があり、別ルームへの移動（参加先の切り替え）でも交代先の確認・解散への同意・途中失敗からの再確認が生じる。退出時には「成果を残す/残さない」を選ばせ、入口によって既定値が異なっていた。いずれも利用者が知らなくてよい内部の区別で、参加先切り替えの不具合の多さにもつながった。

## Decision

ルームの参加者を同じ権限で扱い、ホストを置かない。

- 解散・ホスト移譲を廃止する。参加者の除外とボードからの招待は全員が行える。除外の対象は自分以外の全員で、接続中の人も含む。発表順は参加者全員を抽選する。
- 退出は本人の在籍だけを外し、他の参加者に影響しない。退出・移動した人の成果閲覧権は常に残す。閲覧権を持たせない操作は、他の参加者による除外だけとする。
- ルームは、在籍者がいなくなった時点で終了し、招待URLを無効にする。在籍者が全員切断したまま24時間経過した場合も終了する。タブを閉じる・切断するだけでは退出にしない。
- 退出は誤操作を防ぐため確認を出す。別ルームへの参加・作成では確認せずに元ルームを退出する。退出が他者に影響しなくなるため、同意を求める理由がない。
- 完了後のルーム削除を廃止し、成果は既存の30日期限で消す。完了後は在籍の変更がないため、退出ではなくホームへ戻るだけにする。

RoomDOが在籍・成果閲覧権の真実を持つ点、AccountDOが本人単位で参加先を一つに保つ点は変えない。

### 本ADRで決定しないこと

画面・通信・移行の具体手順はPRD、進行仕様と実装PRへ委譲する。Referencesを参照。

## Consequences

- `hostId`・`hostRevision`・`host:transfer`・解散の意図など、ホストに関する契約とUIを削除する。旧クライアントとの混在中は、ホスト世代付きの要求を拒否せず無視できる形で移行する。既存RoomDOのホスト列はmigrationで消さず、読まなくする。
- 自動進行の担当など内部で一人を選ぶ処理は、接続中の参加者から決定的に選び、画面には出さない。
- 全員が除外できるため、接続中の人を悪意で外す操作を防げない。招待を受けた少人数の共同作業を前提に受け入れる。除外の濫用が観察されたら、対象を切断中の人に限る・取り消せるようにするなどを検討する。
- 24時間の無接続終了はRoomDOのalarmで行う。長時間の休憩をはさむ使い方が確認されたら期限を見直す。
- 0015の確認・取消・再確認の手順は縮小する。旧在籍の整理（導入前の複数参加）も確認せずに、開こうとしたルーム以外から退出する。

## Alternatives Considered

ホストを残して自動交代だけを広げる案は、権限差の説明と交代の競合処理が残るため採らない。最後の在籍者の退出で解散相当の確認を出す案は、影響を受けるのが本人だけなので採らない。誤って参加した人の閲覧権は、招待を開いたときの参加確認と、他の参加者による除外で扱う。
