# 0016: 参加候補を索引化し、WS操作から全ルーム照合を外す

- 状態：提案
- 決定日：未確定（実装PRでレビュー）
- 記録日：2026-10-15
- 前提：[0015](0015-account-room-participation.md)の本人単位の参加制御を維持し、照合方式を変更する。

## 背景

参加先を求めるたびにD1の全ルームを直列照合すると、WS操作の待ち時間がルーム総数に比例する。無関係なRoomDOの障害が操作に波及し、横断照合中の例外やゲートの時間制限でAccountDOをリセットする。

## 候補と決定

AccountDOに参加候補の索引と初回照合の進捗を永続化する。旧在籍は初回だけ公開済み・旧ルームを16件ずつ照合し、成功したページの進捗を保存する。外部RPCは`blockConcurrencyWhile`の外で行い、同時照合の結果はカーソルが一致する場合だけ保存する。完了するまで操作を許可しない。

以後の参加・再訪では候補のRoomDOだけを再照合し、退出・除外・解散・失効・完了した候補を取り除く。参加確定時は移動先の候補と処理済み結果を同じtransactionで保存し、処理中ロックを解除する。専用の検証サンプルなどの再訪先は在籍・未完了の事実を確認して候補へ加える。

解除通知で索引を直接消す方式は採らない。索引は在籍の真実ではなく保守的な候補であり、遅い通知で新しい参加先を消さない。RoomDOは各操作の直前にも自身の在籍・完了状態を検証する。

WS操作のAccountDO照会は、照合完了・候補数・処理中ロックだけを参照し、D1やRoomDOへの逆RPCを行わない。許可結果の接続単位キャッシュは、処理中ロックや同時要求の変化を見落とすため採らない。RoomDO側はディレクトリ存在確認の成功だけを稼働中に再利用し、通信障害は操作拒否として返す。

## 影響と見直す条件

通常のWS操作はルーム総数に依存せず、AccountDOへの照会は残る。新しい参加経路は候補の登録を必須とし、旧コードへの無条件rollbackを避ける。専用経路のサンプル切り替えは旧ルームを閲覧専用にしてから新しい参加先を公開する。

初回の照合費用は引き続き全ルーム数に比例し、未照合ルームの障害時は参加制御を保ったまま再試行する。大量の旧在籍を持つ本人の候補再照合も在籍数に比例する。実データの初回照合時間と通常操作のAccountDO往復時間を計測し、さらなる移行処理・キャッシュが必要か判断する。
