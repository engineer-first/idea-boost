# ADR 0016: 参加候補を索引化し、WS操作から全ルーム照合を外す

## Context

本人の参加先を確認するたびに全ルームを直列照合すると、操作の待ち時間がルーム総数に比例する。無関係なRoomDOの障害がWS操作へ波及し、照合中の例外や実行時間制限が調整役の処理を中断する問題がレビューで指摘された。

## Decision

AccountDOに本人の参加候補と初回照合の進捗を保持する。通常の参加・再訪では候補のRoomDOを再確認し、WS操作から全ルーム照合を外す。候補を在籍の真実とはせず、RoomDOは操作時の在籍と状態を引き続き確認する。単一参加を守りつつ、通常操作が無関係なルーム総数と障害に依存しないようにするためである。

### 本ADRで決定しないこと

関数・通信形式・保存の具体手順と移行方法は、参加先切り替えの運用仕様へ委譲する。参照先はReferencesに示す。

## Consequences

良い影響は、通常のWS操作が全ルーム総数に依存しなくなること。悪い影響は、初回の旧在籍照合と候補登録の保守が必要になること。中立の影響として、AccountDOへの照会は残り、未照合や曖昧な参加状態では操作を拒否する。初回照合時間と通常操作の往復時間が問題になる場合に、移行と照会の方式を見直す。

2026-11-03に実コード・一次資料を照合。根拠未確認：実装または提案記録は確認できるが、オーナーがこの技術方針・比較理由まで採用した元発言は確認できない。実装済みであることだけではAcceptedにしない。

## Alternatives Considered

解除通知だけで候補を消す案は遅い通知で新しい参加を消すおそれがある。許可を接続単位でキャッシュする案は参加切り替え中の変化を見落とすため、実装では候補と現在の状態を照合する。
