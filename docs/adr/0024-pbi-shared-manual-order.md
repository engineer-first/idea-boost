# 0024: PBIの優先順をProjectの共通手動順で管理する

- 状態：採用
- 決定日：2026-10-31
- 記録日：2026-10-31

## 背景

リファインメントで決めた優先順を他ビューでも使いたい。利用者が必要としているのは順序であり、順位の数字や「最優先・高・中・低」の分類ではない。

数値への採番同期はActionsの定期起動の遅延に影響され、Cloudflare Cronへの移行も試した。しかしGitHub Projectsの手動順はProject内で共有されるため、この目的に別の値と同期基盤を追加する必要はなかった。

## 候補と決定

GitHub Projectsの手動順を優先順位の正本とする。リファインメントでドラッグして決め、同じ優先順で見るビューは `Sort by: manual` にする。別の順番で見るビューは、それぞれのソート条件を設定する。

数値への変換・定期同期・操作イベントからの同期はいずれも採用しない。標準の手動順共有で目的を満たせるため。数値列と分類列は対象ビューから非表示にし、採番用Actionsと専用Workerを撤去する。

## 影響と見直す条件

番号の更新や反映待ちがなくなる。一方、別ビューでのドラッグも共通手動順を変えるため、優先順の変更は原則リファインメントで行う。ソート条件を持つビューは、そのソートが手動順に優先する。

既存フィールドや値は記録として保持し、順位の正本にはしない。外部への順位出力、順序の履歴・確定版、独立した複数の優先順が必要になった場合は、その要求に合わせて方式を再検討する。

## 根拠

- 利用者が「数字そのものより、他のビューで優先順に並べたい」と明確化し、標準の手動順共有による運用を承認した。
