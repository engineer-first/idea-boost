# 0010: 入室前だけ認証を準備し、元操作を一度引き継ぐ

- 状態：提案
- 決定日：2026-10-10
- 記録日：2026-10-10

## 背景

共同作業の途中で認証期限に達すると、接続を止めて本文を保護する必要がある。
利用者は入室判定から待機・休憩を含む最低5時間を選び、作業中の自動更新を見送った。
通常のログイン画面は有効な認証があれば省略するため、認証更新の入口としては使えない。

## 候補と決定

入室前の準備だけを採る。Nextで検証したセッションの期限とサーバー時計を比較し、
残り5時間ちょうどを含めて許可する。不足時は明示操作でGoogleへ進み、既存のOIDC検証と
セッション発行を再利用する。JWTとCookieは発行から固定7日を維持し、活動で延長しない。
短命JWT・更新用トークン・作業中の自動更新は、今回の利用契約に不要なので導入しない。

元操作は署名した用途別トークンで本人・対象・操作・OAuth state/nonce・タブ識別子へ限定する。
再開情報の期限は10分。Google検証後も元本人と一致した場合だけ発行し、タブ識別子はURLに出さず
同じタブの保存領域で照合する。本文は本人・ルーム別の既存下書き保存に残し、操作許可として扱わない。
未認証の招待閲覧は同意として扱わず、通常ログインから参加確認へ戻す。

Cookieの削除だけでは並行再送を拒否できないため、API Worker経由でD1へ使用済みIDを一意挿入する。
認証再開と同じ入室の画面遷移を一回だけ消費し、古い情報で退出やキックを取り消さない。
同じ入室の控えは現在の本人・認証の実期限・ルーム・ロビーから盤面への用途に限定する。
控えのタブへの束縛も一回だけとし、盤面への到達で継続用の控えの発行を終える。
入室継続は文書内の控えにも登録し、URLや保存値を複製した別文書で使わない。
新しい入室・再読込・別タブは新たな判定とし、入室後の工程移行や通信復旧に5時間判定を追加しない。

## 影響と見直す条件

実際の作成・参加・復帰は既存のServer Action、API Worker、RoomDOの認可を再確認する。
作成requestIdと結果照会を維持し、認証成功を保存成功と扱わない。
Cookieの更新は既存WebSocketの期限を延長しない。最新snapshotを取得してから共有操作を再開する。

一回消費の通信結果が不明なら自動実行せず、元画面から確認する。タブ閉鎖・別端末への本文回復は保証しない。
ブラウザがOAuth往復中の履歴とタブ保存値を丸ごと複製する操作は、タブ識別子だけで完全には識別できない。
通常の別タブ識別子・state競合を拒否するが、この複製操作の完全な同一タブ保証は検証範囲外とする。
5時間を超える利用や作業中の継続保証が必要になったとき、更新認証と失効方式を別途見直す。
