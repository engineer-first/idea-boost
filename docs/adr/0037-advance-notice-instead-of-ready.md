# ADR 0037: 完了の表明をやめ、誰でも進められる予告つきの進行にする

## Context

ADR 0025 でホストを無くし、進行は参加者全員の操作になった。共有以外のステップでは、各参加者が「できた！」で完了を表明し、接続中の全員がそろうか時間切れになると、誰かが「次のステップへ」を押して進めた。時間切れで未完了の人がいれば、進める人に未完了者の確認を出した。

この進み方では、全14工程のうち共有を除く11工程で、全員が毎回「できた！」を押す必要があった。押し忘れた人が1人いると、時間切れまで進めないか、未完了者の確認を経ることになる。押したかどうかを伝えるために、押し済みの表示、人数待ちの文言、押し忘れへの誘導、完了の演出が操作欄に積み重なった。「できた！」を分かりやすくする改善は検討したが、採らなかった。

RoomDO は、工程ごと・参加者ごとの完了の表明を保存し、接続の増減のたびに全員がそろったかを判定して配っていた。進行の可否は、この判定と時間切れのどちらかで決まり、投票の完了・採用決定・共有の一巡という工程固有の条件とは別に検査していた。

## Decision

完了の表明と全員チェックをやめる。工程固有の条件（投票の完了・採用決定・共有の一巡）を満たしていれば、参加者の誰でもいつでも「次のステップへ」を押せるようにする。全員の合意は、進む前の確認ではなく、進む直前に止められることで取る。

押された要求は、すぐには工程を進めず、全員に5秒の予告を出す。予告の間に誰かが止めれば取り消し、誰も止めなければ進む。予告には、押した人・次のステップ・そこでやること・いまのステップの目安を出し、作業の途中の人が「止めるか、このまま進むか」をその場で決められるようにする。接続中の参加者が1人のときは、止める相手がいないので予告なしで進める。

予告は、人が押した時のほかに2つの場合に自動で出す。投票では、最後の1票で全員が票を使い切った時に出す（手の動きから終わりが分かる唯一の工程のため）。時間切れでは10秒の予告を出し、1回だけ1分延長できるようにする。延長後の時間切れは止められない予告を経て進む。

止めた人は誰にも配らない。初対面の場で「止めた人」として目立つと押しにくくなるためで、全員には止まったことだけを伝える。押した人の名前は出す。

予告の残り時間と取り消しの真実は RoomDO が持つ。進む直前に、工程・更新番号・工程固有の条件を RoomDO がもう一度検査し、予告の間に条件を満たさなくなった要求は進めない。クライアントは配られた終了時刻を表示するだけにし、再接続した人にも同じ残り時間を見せる。

最終ステップの成果の公開には予告を使わず、従来の確認を残す。公開は戻せないため、5秒で流れる予告より、押す人の明示の確認が合う。

### 本ADRで決定しないこと

予告の秒数・文言・見た目、自動で出す条件の細部（接続の増減との関係など）、止められた後の表示は進行仕様へ委譲する。メッセージの形は境界スキーマへ、保存の形は RoomDO の migration へ委譲する。共有の発表者交代（本人の操作ですぐ交代する）は変えない。委譲先へのリンクは References に置く。

## Consequences

- 良い影響：共有以外の11工程で、全員が毎回押す操作が無くなる。押し忘れで進めない状態と、未完了者の確認が無くなる。
- 良い影響：進行の可否が、工程固有の条件だけで決まる。RoomDO は参加者ごとの完了の表明を持たなくなり、操作欄から押し済み表示・人数待ち・誘導・演出が消える。
- 良い影響：次のステップでやることと、いまのステップの目安を、進む直前に全員が同じ画面で読める。
- 悪い影響：5秒は、接続中でも画面を見ていない人には短い。気づかずに進んだときの受け皿は、既存の「直前のステップに戻る」だけになる。
- 悪い影響：早く進めたい人に引っぱられやすい。止めるには、毎回誰かが「まって！」を押す必要がある。止め合いが続く場合の制限は置いていない。
- 悪い影響：時間切れの予告は「勝手に進む」に近い。初対面の場で嫌がられないかは、実際の会で確かめていない。
- 悪い影響：止めた人を出さないので、誰を待っているかが画面から分からない。再開のきっかけは、声をかけるか、止めた本人が押すことに頼る。
- 中立：開いたままの古い画面と新しい RoomDO が同時に動く間、古い画面には予告の帯が出ない。古い画面で「次のステップへ」を押すと、5秒後に進む。古い画面の「できた！」は RoomDO が受け取っても何も変えない。完了の表明の保存先は読まなくなるが、migration では消さない。
- 保証しない範囲：予告の間に誰も画面を見ていなかった場合の合意。投票の完了は接続中の参加者で判定するため、切断中の人の票は待たない（従来と同じ）。
- 見直す条件：
  - 進んだ直後に「直前のステップに戻る」が続けて使われるとき。予告の秒数か、工程ごとの長さを見直す。
  - 止め合いで進めない会が観察されたとき。
  - 誰を待っているか分からず止まったままになる会が観察されたとき。止めた人を出すかを見直す。

## Alternatives Considered

- 「できた！」を残して分かりやすくする：押し忘れと毎回の手間は残る。採らない。
- 手の動きから終わりを自動で判定する：書く・整理する・評価する工程では、手が止まったことと終わったことを区別できず、満足度を下げる。票を使い切る投票だけに採用した。
- 時間だけで進む：初対面の場で勝手に進むのを避けたい。止められる予告として採用した。
- 先に行ける人は先へ進み、次の工程で待つ：待っている人に進むよう促す役が要り、ホストを置かない判断と合わない。採らない。
- ステップを薄くして数を減らす：個人で書く工程と共有する工程を分ける型を残したい。採らない。
- 止めた人の名前を出す：誰を待っているかが分かり声をかけやすいが、初対面では止めた人として目立ち、押しにくくなる。採らない。

## Related ADRs

- ADR 0025：ルームにホストを置かず、進行を参加者全員の操作にする。この判断は残し、本 ADR は「全員がそろってから誰かが進める」を「誰かが進め、全員が止められる」に変える。ADR 0025 が挙げた「誰でも進行できるので、早すぎる進行が起きうる」への歯止めは、完了条件と時間切れから、予告と工程固有の条件に変わる。
