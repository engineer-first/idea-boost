# ADR 0032: 3票のシールは課題・問いでは「いいね」、アイデアでは「需要ありそう」と呼ぶ

## Context

ADR 0028 で、1人3票のシール（内部名 `objective`）の画面の名前を「需要ありそう」とし、表記をどこでもそろえると決めた。

その後のオーナーの操作確認で、アイデアの投票では「需要ありそう」がしっくり来る一方、課題（困りごと）や問いの投票では「需要」という言葉が合わず違和感がある、と挙がった。ADR 0028 の比較でも、アイデアには自然でも課題に貼ると不自然になる名前があることは分かっていた。

## Decision

1人3票のシールの画面の名前を、フェーズで呼び分ける。

- 課題（1-4）と問い（2-3）のフェーズでは「いいね」と呼ぶ。
- アイデア（3-4）のフェーズでは、これまでどおり「需要ありそう」と呼ぶ。
- 「イチオシ！」の名前、基準の一文（「自分以外の人にも価値がありそう」）、票数、点数、色、形、種類のタグ（「客観」）は変えない。

フェーズごとに別の言葉を用意せず、課題・問いで共通の短い言葉にする。覚える名前を増やさず、「イチオシ！」との違いを保つためである。基準の一文はステップガイドで名前と並べて示し続けるので、「自分以外の誰かのため」という意味は基準の側で伝える。

ADR 0028 のうち、内部の種別名 `subjective` / `objective` を変えないこと、基準の一文をパレットに出さずステップガイドで示すことは、そのまま引き継ぐ。変えるのは「表記はどこでもこの形にそろえる」の部分だけである。

### 本ADRで決定しないこと

どの画面がどのフェーズの名前を使うか、名前の引き方（関数・定数）は用語集と実装に委譲する。LP の盤面はアイデアのフェーズを例に見せるため「需要ありそう」を使う。

## Consequences

- 良い影響：課題・問いの投票で、シールの名前が貼る対象に合う。
- 悪い影響（受け入れるリスク）：同じシールがフェーズで別の名前になる。運営向けの記録や文書のように複数のフェーズをまとめて書く場所では、「需要ありそう（課題・問いでは「いいね」）」のように添える必要がある。
- 悪い影響：ADR 0028 の比較で、「いいね」は弱い好みとして使われ、自分以外の誰かのためという意味が消えると指摘されていた。基準の一文をステップガイドで示すことで補う。
- 悪い影響：共有のリアクションにも「いいね」があり、言葉が重なる。用語集で別のものと明記する。
- 判断の出どころ：「いいね」はオーナーが要望の例として挙げた言葉で、ほかの候補との比較と選択はループ（AI）による。
- 見直す条件：課題・問いの投票で「いいね」を弱い好みとして使い、3票を誰かのためという基準から外れて貼る様子が多く見られたとき。

## Alternatives Considered

- 「共感できる」：課題には合うが、問いには合いにくい。「イチオシ！」の基準「激しく共感する」とも言葉が重なる。
- 「みんな困ってそう」（課題）／「みんなに効きそう」（問い）：基準の意味をよく表すが、フェーズごとに別の名前になり、覚える名前が増える。
- 全フェーズで「いいね」にする：アイデアでは「需要ありそう」が合うとオーナーが評価していたため選ばなかった。
