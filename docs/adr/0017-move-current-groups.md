# 0017: 付箋移動はドロップ時の分類から確定する

- 状態：提案
- 決定日：未確定
- 記録日：2026-10-16
- 前の判断：[0006](0006-move-transactions.md)の通常移動における分類版の検査

## 背景

移動開始時のルーム全体の分類版を確定時にも要求すると、別の参加者が別の付箋を動かしただけで進行中のドラッグが取り消される。分類は付箋を離した位置から再編されるため、開始時の分類を固定する必要はない。一方、対象付箋そのものの競合、不可視な分類の変更、Undoによる他者の更新の巻き戻しは防ぐ必要がある。

## 候補と決定

通常移動の開始・途中表示・確定では、分類全体の版が変わっただけでは取り消さない。RoomDOは確定直前の分類と版を読み、その分類に移動後の位置を適用する。位置・分類・成功記録は従来どおり同じtransactionで保存する。成功記録の分類変更前の版も確定直前のものとする。

全体の分類版を一致条件にする方式は、独立した同時操作を不必要に拒否するため採らない。開始時の分類を上書きする方式も他者が付けた名前や所属を消すため採らない。対象全件の位置・可視性版、lock、接続所有者、工程・map版、現在の参加権限は引き続き検査する。Undo/Redoは保存済みの分類を復元する操作なので、影響する分類IDごとの版を引き続き検査する。

## 影響と見直す条件

二人が同時に別の付箋を動かせる。先に確定した移動の分類を次の移動が引き継ぐため、最終分類はRoomDOでの確定順に決まる。分類の変更で付箋の位置・座標系まで変える機能を導入するときは、その変更の専用版も含めて競合条件を見直す。

WSの形・保存スキーマ・共有済み付箋の移動権限は変更しない。分類版は状態通知と成功記録に残し、古いクライアントからの要求も同じ確定規則で処理する。
