# ADR 0007: ルーム作成要求を削除後も保持する

## Context

ルーム作成は横断ディレクトリの予約とRoomDOの初期化にまたがる。応答喪失後の再送を新しい作成と扱うと、一度の作成意図から複数のルームができる。要求との対応をルーム削除と一緒に失うと、遅い再送でルームを復活させる可能性もあった。

## Decision

利用者と作成意図を対応付ける記録をルーム削除後も保持し、同じ作成の再送を同じ結果へ収束させる案を提案した。保持期限が決まるまでは自動削除せず、終了済みルームの再初期化を拒否する。通信の結果が分からないことを、新しい作成を許す理由にしないためである。

### 本ADRで決定しないこと

関数・通信形式・保存の具体手順と移行方法は、ルーム作成の運用仕様へ委譲する。参照先はReferencesに示す。

## Consequences

良い影響は、途中失敗と遅い再送による二重作成・復活を防げること。悪い影響は、要求数に比例して名前を含む記録を永久に増やすこと。中立の影響として、要求を保持してもルームや成果を利用できる期間は延びない。保持期間とデータ削除の要求が明確になったことから、後継案では受付期限と回復情報の寿命を分けている。

2026-11-03に実コード・一次資料を照合。旧提案の個別の採用承認は根拠未確認。後継本文は新しい提案として別に評価する。現コードは永久保持案から後継の有限受付方式へ変わっている。

## Alternatives Considered

有限の対応表だけを消す案では、古い再送を新規作成と区別できない。短期の詳細と長期の墓標を分けても、最終的に墓標を消すには古い要求を拒否する別の境界が必要になる。
