# 全14ステップのデモ台本とサンプル一覧

## このデモで伝えること

**課題を集め、問いに変え、アイデアを比較して選ぶ。各ステップの目的を、5人の具体例で説明する。** デモの所要時間や制限時間は設定しない。操作や説明に必要なだけ時間を取り、全14ステップを順番に見せる。

各フェーズに8枚、合計24枚のサンプルを用意する。ホスト・あおい・けんたは各2枚、みさき・りくは各1枚。全員が少なくとも1枚を持ち、ホスト自身も入力なしで進められる。

- 最初に「今回は私が1人分を操作し、残り4人は用意したデモ参加者です」と紹介する。
- 「進め方」は何をすべきかの説明、「考えるヒント」は考え始めるための支援、「デモ操作」は説明者がサンプルを操作するための補助として区別する。
- アプリ本体のワーク用タイマーは任意に紹介できるが、デモ時間の指定・制限・待ち時間としては使わない。
- 個人付箋は本人だけに見える。全員のデータが保存されていることと、画面で全員分を公開することは別。共有は説明者の操作・合図で行う。
- 同じ操作は後半で短く説明してよいが、そのステップで何を考えるかと具体例は必ず示す。

## 起動と進め方

[READMEの起動手順](../README.md#1人で5人チームを実演するローカルデモ)に従い `npm run demo` を実行する。通常の `npm run dev` ではデモを有効にしない。

1. `/demo` から「1-1 自分の課題（個人）」を選んで開始する。
2. 自分の2枚を見せ、必要なら編集する。通常の進行ボタンで次のステップへ進む。
3. 各共有ステップで自分の2枚をドラッグ共有し、「他4人が共有する」を押す。
4. 各投票ステップで自分の赤1票・青3票を投じ、「他4人が投票する」を押す。
5. 決定ステップでは結果を示し、自分で採用する。課題・HMWは次のフェーズへ引き継がれる。
6. HMW・アイデアの個人ワークへ入ると、そのフェーズの下書きが自動で用意される。自分の2枚を使い、同じ流れで進める。

各ステップから直接始めることもできる。「見せ場へ移動」「やり直す」は新しいルームを作るため、直前の自由入力や選択は引き継がない。課題から決定までの一連の流れを見せる場合は、同じルームで通常の進行操作を使う。

データが更新される前に作ったルームを練習で使っていた場合は、入口から新しいデモを開始する。既存ルームの編集内容を更新のために上書きすることはしない。

## 自動で用意することと、手動で見せること

| 内容           | 自動で用意すること                                      | あなたが見せる操作                                                                       |
| -------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 個人ワーク     | 全員分の下書き。本人には自分の2枚が見える               | 用意された内容を紹介する。必要なら1枚を編集・追加する                                    |
| 共有           | 他4人の公開前の下書き6枚                                | 自分の2枚を共有し、他4人の共有を合図する                                                 |
| 1-3 グループ化 | 直接開始なら4枚ずつの2グループを命名済み                | 名前の変更、付箋の移動、まとまりを説明する。通し進行なら「グループ例を配置する」も使える |
| 投票           | 他4人が投じるサンプルへの票の配分                       | 自分の4票を投じ、他4人の投票を合図する                                                   |
| 決定           | 直接開始なら全員の投票を用意。3-5直接開始は採用まで完了 | 通し進行では自分で採用し、理由を説明する                                                 |
| HMW            | 決定課題と8枚の問いの例                                 | テンプレートの役割を紹介し、任意に編集・追加する                                         |
| アイデア       | 課題・HMW、8案と比較用の配置                            | 発想ヒント、比較する理由、2軸での移動、採用理由を見せる                                  |

「他4人が共有する」「他4人が投票する」は、自分の共有・投票を代行しない。共有済み・投票済みの合図を再度押しても重複しない。

## 1-3で実際に見せるグループ例

共有された課題8枚を、次の2グループへまとめる。

| 用意したグループ名 | 含まれる人と課題                                                                                               | まとめる理由                                         |
| ------------------ | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 学び合う相手探し   | ホスト：仲間がいない、あおい：空き時間がわからない、けんた：質問相手がほしい・授業外でつながれない             | 学ぶ意欲があっても、一緒に学ぶ相手との接点が足りない |
| 昼休みの混雑       | みさき：昼休みが足りない、りく：席探しで疲れる、ホスト：次の授業に間に合うか不安、あおい：空く時間がわからない | 混雑の状況がわからず、昼休みを使いにくい             |

### 手動入力の例

1. 「1-3 グループ化」から始めると、2グループができた状態になる。
2. 「学び合う相手探し」のグループ名をクリックする。
3. 次の名前を入力して確定する。

> 空きコマに学び合える仲間がほしい

4. 「分類名だけでなく、共通する困りごとを表した名前にもできます」と説明する。
5. 付箋を少し動かし、個々の内容を残したまままとまりを調整できることを見せる。

1-1から順に進めた場合は、1-2で8枚を共有してから1-3へ進み、「グループ例を配置する」を押す。8枚の位置とグループ名が例の状態に戻るため、手動で変更した名前を保存しておきたい場合は再度押さない。自分で一からまとめて名前を付けることもできる。

## 全ステップの台本

導入の例：

> 学生5人で、学生生活の困りごとを解決するアプリを考えます。何から考えるか、どう意見を集めるか、どれを選ぶかを、画面の流れに沿って進めます。各場面の具体例を見ながら説明します。

### 1-1 自分の課題（個人）

**目的**：全員が自分の困りごとを出し、話す人だけに意見が偏らないようにする。

**用意されるもの**：各フェーズに8枚（ホスト・あおい・けんたが2枚ずつ、みさき・りくが1枚ずつ）。個人ワークでは自分の2枚だけが見えます。

**あなたの操作**

1. 進め方と5人のメンバーを紹介し、「マイ付箋」を開く。
2. 自分のサンプルを選んで編集する。入力は必須ではなく、用意されたままでも進められる。
3. 自分の2枚を確認して共有へ進む。

**入力・説明に使う例**

- 取り組む課題の例：空きコマに一緒に勉強する仲間が見つからない
- 編集するなら：空きコマに、同じ授業の友達と一緒に課題を進めたい

**話す内容の例**

> まず一人ずつ困りごとを書きます。ここでは自分の付箋だけが見え、共有してから他の人にも見えるようになります。

### 1-2 課題共有

**目的**：5人それぞれの困りごとを見せ、共通点と違いを見つける。

**用意されるもの**：全員の下書き8枚。共有は自動で進まず、自分の2枚は手動、他4人の6枚は合図で公開します。

**あなたの操作**

1. 自分の2枚を共有スペースへドラッグする。
2. 「他4人が共有する」を押し、共有4/4人を確認する。
3. 内容を紹介したら通常の進行ボタンで次へ進む。

**入力・説明に使う例**

- 共通する困りごと：勉強仲間が見つからない／友達の空き時間がわからない／質問相手がほしい
- 別のテーマ：学食が混む／空いている場所がわからない／席を探して昼休みが終わる

**話す内容の例**

> 全員の8枚が出ると、学び合う相手探しと、昼休みの混雑という二つの話題が見えてきます。

### 1-3 グループ化

**目的**：似た課題をまとめ、共通する意味をグループ名として言葉にする。

**用意されるもの**：この見せ場から開始すると8枚を2つの名前付きグループに配置済みです。1-2から順に進めた場合は、自分の2枚と他4人の6枚を共有してから例を配置できます。

**あなたの操作**

1. 必要なら「グループ例を配置する」を押す。デモ用付箋の位置とグループ名が例の状態に戻る。
2. グループ名をクリックして、下の変更例を入力する。付箋を動かし、まとまり方も変えてみる。
3. 投票はグループ名ではなく個々の付箋に行うと伝え、次へ進む。

**入力・説明に使う例**

- 学習の4枚をまとめる名前：学び合う相手探し
- 昼休みの4枚をまとめる名前：昼休みの混雑
- 手動で変更するグループ名：空きコマに学び合える仲間がほしい

**話す内容の例**

> 同じ内容を消して一枚にするのではなく、一人ひとりの課題を残したまままとめます。名前を付けることで、このチームが何に困っているかを説明できます。

### 1-4 投票

**目的**：他人の票に引っ張られず、取り組む課題への支持を集める。

**用意されるもの**：この見せ場から開始すると、8枚を2グループに整理済みで、投票は全員未実施です。

**あなたの操作**

1. 自分の赤1票・青3票を、取り組みたい候補や判断基準に合う候補へ投じる。
2. 「他4人が投票する」を押し、投票4/4人を確認する。
3. 通常の進行ボタンで結果の場面へ進む。

**入力・説明に使う例**

- 赤票の判断例：自分が取り組みたい、解決してみたい課題
- 青票の判断例：困っている人が身近にいて、解決すると助かる課題
- 採用候補：空きコマに一緒に勉強する仲間が見つからない

**話す内容の例**

> 赤は自分の思い、青は話し合った基準をもとに投じます。投票中は他の人の票が見えず、結果の場面で全員分を確認します。

### 1-5 課題決定

**目的**：票を参考に、次に考える課題を一つ決める。

**用意されるもの**：この見せ場から開始すると全員の投票を用意し、採用はまだ行っていません。

**あなたの操作**

1. 投票結果を示し、課題を選ぶ理由を話す。
2. 下の採用候補を選んで決定する。自由に別の付箋を採用することもできる。
3. 次へ進み、HMW画面に課題が引き継がれたことを確認する。

**入力・説明に使う例**

- 採用する課題：空きコマに一緒に勉強する仲間が見つからない
- 選ぶ理由：学習に関する複数の困りごとの中心にあり、自分たちの学生生活で確かめられる

**話す内容の例**

> 票だけで自動決定するのではなく、理由を話して課題を選びます。今回は勉強仲間が見つからない課題を、次の問いへつなげます。

### 2-1 課題に対するHMW（個人）

**目的**：決めた課題を、解決策を広げられる「どうすれば？」という問いに変える。

**用意されるもの**：決定した課題と、HMWの下書き8枚。各フェーズに8枚（ホスト・あおい・けんたが2枚ずつ、みさき・りくが1枚ずつ）。個人ワークでは自分の2枚だけが見えます。

**あなたの操作**

1. 「マイ付箋」を開き、引き継がれた課題と自分の2枚のHMWを紹介する。
2. サンプルを編集するか、「考えるヒント」のテンプレートから追加の1枚を作る。
3. 手入力しなくても、用意された2枚を使って共有へ進める。

**入力・説明に使う例**

- 採用候補のHMW：どうすれば、空きコマに気軽に学び合う仲間と出会えるだろう？
- テンプレートから書く例：どうすれば、もっと安心して初対面の勉強仲間に声をかけられるだろう？

**話す内容の例**

> いきなり機能名を考える前に、何を実現したいかを問いにします。「気軽に出会えるには？」と置くと、声かけや仲間探しなど複数の解決策を考えられます。

### 2-2 HMW共有

**目的**：同じ課題にも、出会い・安心感・短い空き時間など異なる切り口があると示す。

**用意されるもの**：5人のHMW下書き8枚。ホストを含む全員が、同じ決定課題をもとにした例を持っています。

**あなたの操作**

1. 自分の2枚を共有スペースへドラッグする。
2. 「他4人が共有する」を押し、共有4/4人を確認する。
3. 内容を紹介したら通常の進行ボタンで次へ進む。

**入力・説明に使う例**

- 切り口の比較：今いっしょに勉強できる人を知る／初対面でも質問しやすくする／誘う負担を減らす

**話す内容の例**

> 共有操作は先ほどと同じです。ここでは同じ困りごとに対して、どんな問いを立てるかの違いを見てください。

### 2-3 投票

**目的**：課題に合い、いろいろな解決策を考えられる問いを選ぶ。

**用意されるもの**：この見せ場から開始するとHMW8枚を共有済みで、全員未投票です。

**あなたの操作**

1. 自分の赤1票・青3票を、取り組みたい候補や判断基準に合う候補へ投じる。
2. 「他4人が投票する」を押し、投票4/4人を確認する。
3. 通常の進行ボタンで結果の場面へ進む。

**入力・説明に使う例**

- 比較する基準：選んだ課題に答えているか／特定の機能に決めつけず発想を広げられるか
- 採用候補：どうすれば、空きコマに気軽に学び合う仲間と出会えるだろう？

**話す内容の例**

> 投票方法は同じです。今回は、何を作るかを先に決めすぎず、解決策を広げられる問いに注目します。

### 2-4 HMW決定

**目的**：チームがこれから答えを考える問いを、一つに揃える。

**用意されるもの**：この見せ場から開始するとHMW8枚と全員の票を用意済みです。課題は引き継ぎ、HMWの採用は手動で行います。

**あなたの操作**

1. 下のHMWを選び、採用を決定する。
2. 課題とのつながりを話し、次へ進む。
3. アイデア画面に課題とHMWの両方が残ることを示す。

**入力・説明に使う例**

- 採用するHMW：どうすれば、空きコマに気軽に学び合う仲間と出会えるだろう？
- 選ぶ理由：仲間との出会いを中心にしながら、募集・声かけ・短い交流など複数の方法を考えられる

**話す内容の例**

> 何に困っているかに加えて、何を考えるかが決まりました。この問いに答える具体的な方法が、次のアイデアです。

### 3-1 アイデアを書き出す（個人）

**目的**：HMWに答える具体的な方法を出す。手が止まったときの発想支援も示す。

**用意されるもの**：課題・HMWの引継ぎとアイデア下書き8枚。各フェーズに8枚（ホスト・あおい・けんたが2枚ずつ、みさき・りくが1枚ずつ）。個人ワークでは自分の2枚だけが見えます。

**あなたの操作**

1. 「マイ付箋」を開いて自分の2枚を紹介し、必要なら編集する。
2. 「考えるヒント」→「発想を広げる」でSCAMPERの「組み合わせる」を示す。
3. 追加する場合は「書き出し」のヒントから1枚作り、具体的なアイデアに編集する。入力は必須ではない。

**入力・説明に使う例**

- 用意した採用候補：空きコマ勉強マッチ：科目・空き時間の募集にワンタップで参加
- 発想法から説明する例：「空き時間」と「学びたい科目」を組み合わせ、今参加できる勉強の募集を探す
- 追加で手入力する例：今日の一問募集：いま聞きたい質問を一つ書いて、同じ授業の人を募る

**話す内容の例**

> HMWに対して、募集ボード、マップ、質問の場など違う解決策を出します。ヒントは答えを自動生成する機能ではなく、自分たちの発想を広げる切り口です。

### 3-2 共有・分類（チーム）

**目的**：各案を紹介し、同じ課題に対する方法の違いをマップ上で比べ始める。

**用意されるもの**：5人のアイデア下書き8枚。共有すると価値と実現のしやすさの2軸マップに並びます。

**あなたの操作**

1. 自分の2枚を共有スペースへドラッグする。
2. 「他4人が共有する」を押し、共有4/4人を確認する。
3. 内容を紹介したら通常の進行ボタンで次へ進む。

**入力・説明に使う例**

- 比べる方法：科目・空き時間で募集に参加／キャンパスマップで探す／匿名で質問する

**話す内容の例**

> 共有は同じ操作です。課題整理の名前付きグループとは違い、ここでは案を2軸マップに置いて比較していきます。

### 3-3 価値×実現のしやすさで評価

**目的**：今回の課題に対する価値と実現のしやすさを、別々の軸で話し合う。

**用意されるもの**：この見せ場から開始するとアイデア8枚を比較用の位置に配置済みです。位置はデモの仮説で、評価や開発見積もりの事実ではありません。

**あなたの操作**

1. 縦軸が課題への価値、横軸が実現のしやすさだと示す。
2. 募集に参加する案とマップで探す案を比べ、理由を話しながら2枚を動かす。
3. 匿名質問箱など、別の強みを持つ案も一つ紹介する。

**入力・説明に使う例**

- 募集に参加する案：募集と参加から試せる。位置情報の自動追跡は入れず、科目と空き時間でつながる
- マップで探す案：近くの相手が見つかる一方、位置情報や更新の扱いを考える必要がある
- 匿名質問箱：質問には役立つが、空きコマに勉強仲間と出会う価値は相対的に低い

**話す内容の例**

> 便利そうかと、実現しやすいかは別の話です。例えばマップは場所がわかる強みがあり、募集への参加なら小さな範囲から試せます。理由を共有して、位置を変えていきます。

### 3-4 ドット投票

**目的**：比較した理由を踏まえ、作って試したいアイデアへの支持を集める。

**用意されるもの**：この見せ場から開始すると、比較用に配置した8枚があり、投票は全員未実施です。

**あなたの操作**

1. 自分の赤1票・青3票を、取り組みたい候補や判断基準に合う候補へ投じる。
2. 「他4人が投票する」を押し、投票4/4人を確認する。
3. 通常の進行ボタンで結果の場面へ進む。

**入力・説明に使う例**

- 判断すること：決めた課題・HMWに答えているか／価値を確かめる小さな形で試せるか
- 採用候補：空きコマ勉強マッチ：科目・空き時間の募集にワンタップで参加

**話す内容の例**

> 投票の方法は同じです。今度はマップ上で話した理由を思い出して、試したい案を選びます。

### 3-5 アイデアを決定

**目的**：アイデアを採用し、課題から決定までのつながりを振り返る。

**用意されるもの**：この見せ場から開始すると投票と採用まで完了した例を表示します。3-4から順に進めた場合は、結果を見て自分で採用します。

**あなたの操作**

1. 通しで進めた場合は、結果を参考に下のアイデアを採用する。

## 3-3で比較するときの根拠

配置はデモの仮説。実際の開発見積もりや利用者調査の結果として説明しない。作る期間や人数を実現性の前提として決めつけず、機能の範囲や必要な仕組みの違いを説明する。

| アイデア                 | 具体的に話す違い                                                                 |
| ------------------------ | -------------------------------------------------------------------------------- |
| 空きコマ勉強マッチ       | 募集と参加を中心に始められ、仲間探しに直接つながる。位置情報の自動追跡は含めない |
| キャンパスマップ         | 近くの相手が見つかる強みがある。位置情報や更新の扱いを考える必要がある           |

「15分質問カフェ」の数字はサンプルのサービス案の名前であり、デモの所要時間・制限時間ではない。

## 自由に変えたときの扱い

- 自分の下書きは編集・削除できる。同じルームへの再接続では、消したサンプルを再作成しない。「見せ場へ移動」「やり直す」は新しいルームを作るため、サンプルを初期状態で用意する。
- 他4人の共有・投票は、用意されたサンプルを対象にする。サンプルの投票先が欠けている場合は、共有済みの別サンプルへ固定順で配分する。任意に追加した付箋のランダムIDを理由に投票先を変えることはない。
- 共有済みサンプルがなくなった場合、他4人の投票は実行できない。必要なら新しいデモルームで開始する。
- 手動で追加した付箋にも自分で投票・採用できる。ただし他4人の固定文言や支持は、選択した別の課題へ自動で書き換わらない。
- グループ例の配置は8枚のサンプルが共有済みであることが前提。共有を終える前に8枚が揃ったことを確認する。1-3へ進んでから不足に気づいた場合は、「見せ場へ移動」で1-3を選び、新しいルームの共有済み8枚から再開する。元ルームの手動変更は引き継がない。
- 最高得点の付箋が自動採用されるわけではない。結果を判断材料に、採用する理由を説明する。

## 理解できたかを確かめる観点

- 1-1〜1-5で、個人で考える・共有する・まとめる・投票する・選ぶ、の違いが具体例からわかる。
- 2-1〜2-4で、課題をHMWに変える目的と、同じ課題にも複数の問いを立てられることがわかる。
- 3-1〜3-5で、発想支援、価値と実現のしやすさの比較、採用理由のつながりがわかる。
- 各フェーズで5人全員が少なくとも1枚を出し、ホストだけのアイデア出しになっていない。
- 自動準備と手動操作の違いがわかり、説明者がその場で全データを入力しなくても実演できる。
- 最後に課題・HMW・採用アイデアを順番に示して、一連の流れを言葉で振り返れる。

このアプリ内で説明する範囲は課題整理からアイデア決定まで。プロトタイプ作成やユーザーテストまで完了したとは説明しない。
