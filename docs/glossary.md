# 用語集

画面・文書・コード・Issueで同じものを同じ名前で呼ぶための正本。
画面の文言を足す・変えるときは、先にこの表で呼び方を確かめる。新しい呼び方を決めたら、この表を同じPRで更新する。

画面の見た目や配置は変わりやすいため、ここには書かない。言葉と意味、コード上の名前だけを書く。

## 投票

| 呼び方       | 意味                                                                                                                                                                                   | コード上の名前                         | 使わない言い方                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | -------------------------------------- |
| イチオシ！   | 1人1票のシール。基準は「激しく共感する、取り組みたい」。5ポイントで数える。                                                                                                            | `subjective`                           | 主観票、主観ドット                     |
| 需要ありそう | 1人3票のシール。基準は「自分以外の人にも価値がありそう」。同じ付箋に重ねて貼れる。1ポイントで数える。                                                                                  | `objective`                            | 客観票、客観ドット、「需要ありそう！」 |
| 主観         | 「イチオシ！」の種類を示すタグ。シールの名前の代わりには使わず、名前に添える（「イチオシ！（主観）」）。                                                                               | `DOT_VOTE_KIND_TAGS.subjective`        | —                                      |
| 客観         | 「需要ありそう」の種類を示すタグ。シールの名前の代わりには使わず、名前に添える（「需要ありそう（客観）」）。                                                                           | `DOT_VOTE_KIND_TAGS.objective`         | —                                      |
| シール       | 投票で付箋に貼るもの。読み上げでは「「イチオシ！」シール」のように名前を鉤括弧で囲む。数え方は「票」。                                                                                 | `DotVoteSticker`、`dotVoteStickerName` | ドット（画面では使わない）             |
| 投票パレット | 投票ステップで、シールの種類のタグ・名前・残票を出し、シールを選んだりドラッグしたりする置き場。使い切った種類を押すと、その種類の自分の最新の1票を1つ取り消す。基準の一文は出さない。 | `DotVotePalette`                       | —                                      |
| 除外         | 決定ステップで付箋を一時的に候補から外す操作。ボタンは「除外」、状態のタグは「除外済み」、元に戻す操作は「除外を戻す」と書く。                                                         | `excluded`、`onExclude`、`onRestore`   | 候補外（画面では使わない）             |

コード上の `subjective` / `objective` は保存データとプロトコルの互換のために残している（[ADR 0028](adr/0028-vote-sticker-display-names.md)。内部名を変えない方針はオーナーが選んだ。3範囲をすべて改名しない比較はAIの提案で、オーナーの確認待ち）。画面に出す名前は `features/dot-vote/logic/dot-vote.ts` の `DOT_VOTE_LABELS`、種類のタグは同じファイルの `DOT_VOTE_KIND_TAGS` から使う。dot-vote に依存しない LP（`landing-board-copy.ts`・`landing-copy.ts`）と運営画面（`shared-outcome-board.tsx`）は同じ名前を写して持つので、名前を変えるときはこの3か所も直す。

文書では、デザインスプリントの元の手法を指すときだけ「主観・客観の投票」と書いてよい。

## 開発の進め方

画面には出ないが、Issue・PR のラベルと文書で使う呼び方。仕組みは[ループ開発](loop/README.md)。

| 呼び方   | 意味                                                                                     | コード上の名前                   | 使わない言い方         |
| -------- | ---------------------------------------------------------------------------------------- | -------------------------------- | ---------------------- |
| ループ   | エージェントが「1周1仕事」で、人が起動しなくても改善から本番公開までを回す開発の進め方。 | `loop:*` ラベル、`scripts/loop/` | ボット、自動開発       |
| 完成台帳 | PRD のうち「壊れていたら困る」振る舞いと、その確かめ方を置いた一覧。                     | `docs/loop/completion.json`      | 完成リスト、機能一覧   |
| 所見     | 巡回が画面を歩いて見つけた問題。S1〜S3 の重大度を付ける。                                | `loop:ux` ラベル                 | 指摘（レビューと区別） |
