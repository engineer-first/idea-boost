# キャンバス操作 — 3分の概要

> **状態: 設計仕様・未実装。** 選択/手のひらモデルとdrop確定共有は承認済み。細部の実装、人による操作確認、応答性能の測定は未完了。

初学者が「画面を見る」「付箋を操作する」「工程を進める」を区別できる操作モデルです。この概要は方針を読む入口。実装・AI・レビューは、同じMarkdownの[実装用詳細（32規則と受け入れ条件）](canvas-interactions/details.md)を参照します。

## 使う操作

| やりたいこと       | 操作と結果                                                                                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 付箋を選ぶ・動かす | 通常は**選択（V）**。クリックで選択、付箋dragで移動、空白dragで矩形選択。Shift+clickで追加/解除。複数選択の一括操作は相対移動だけ。                         |
| 画面を見る         | **手のひら（H）**でpan。Space保持または中ボタンは一時panで、付箋上でも画面だけが動く。解除後は元ツールへ戻る。                                              |
| 文字を編集する     | 選択済み1枚への再click/Enter/文字入力。本文・IME・入力欄では通常のキー操作を優先し、V/Hを文字入力から奪わない。                                             |
| マイ付箋を共有する | 自分の付箋を共有Step2でボードへdrag。**有効dropまで本人だけのpreview**で、pointerupの要求をRoomDOが受理して初めて共有。境界を跨ぐだけでは公開しない。       |
| 操作を中止する     | **Escapeで内側から1段だけ取消**。drag中なら未確定previewを破棄。送信後の結果不明は照会し、公開や保存を取り消したと表示しない。                              |
| 移動を戻す         | 「移動を元に戻す/やり直す」、Ctrl/Cmd+ZとShift追加。1drag=1履歴、複数移動も一括。他者の変更・削除・lockと競合すれば全件拒否し、他者本文や票を上書きしない。 |

## 権限と確定の考え方

- **ツールと工程権限は別。** 選択しても編集・移動・共有の権限は増えません。投票・採用・候補整理・進行は既存の工程コマンドです。工程・役割・可視性の正本は[進行仕様](sprint-flow.md)。
- **表示は即応、保存は終端。** drag閾値を越えたらネットワークACKを待たず本人previewを追従させ、pointerupで位置とgroup副作用を原子的に確定します。未受理を保存済みとは表示しません。
- **取消とUndoは別。** 未確定操作は中止、確定した移動は現在の権限と位置/可視性/group版を再検証して逆操作。1-3ではgroupのID・名前・所属も安全に戻せることが必須です。

## 今回の範囲

選択/手のひら、矩形・複数移動、drop確定共有、取消、移動Undo/Redoの設計です。通常ボードと評価mapに適用し、個人カメラと共有評価座標を区別します。将来のペンは拡張境界だけを記載し、v1に描画機能やボタンは追加しません。

現行は空白drag=pan、共有境界通過でpublish、移動途中も保存するため、UIだけでなくRoomDO/通信契約の改修が必要です。移動以外の汎用Undo、一括削除/共有/採用、group背景の束移動は対象外。タッチは既存操作を維持し、追加gestureは別評価です。
