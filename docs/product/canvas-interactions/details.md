## 1. 目的・正本・読み方

初学者が「今は画面を見る操作か、付箋に働きかける操作か、工程を進める操作か」を区別できるようにする。[3分の概要](../canvas-interactions.md)から来た実装者・AI・レビュー担当が、同じMarkdownの操作契約を参照する。

- 要求の正本は [PRD](../../prd.md)。工程・可視性・役割・機能可否の正本は [進行仕様](../sprint-flow.md)。この文書は入力、選択、移動、モードの詳細を定める。
- `MUST` / `MUST NOT` はv1の必須契約、`SHOULD` は理由を記録した例外を許す推奨。設計メモ・比較調査は説明であり権限を増やさない。
- 規則ID `CI-領域-連番` は永久識別子。改訂しても同じ責務なら維持し、廃止IDは再利用しない。検証IDは `AT-連番`、FigJamの区画は `VS-連番`。
- 現行実装との一致は「現行」節だけで述べる。v1規則を実装済みと読まない。`inherited` は既存要件の継承、`v1` はこの操作モデルの設計、`future` は実装対象外。
- 競合したら、プライバシー・役割・工程の制約を緩めず停止して差分を報告する。FigJamやIssueで正本を上書きしない。要求変更はPRD/進行仕様と当該規則を同じPRで更新する。
- [FigJam Visual Spec](https://www.figma.com/board/bpWlMnyv0Z9pvq7mMeQ0dj) はこの文書の説明図。仕様の独立した正本にしない。

## 2. 全体操作モデル

### 2.1 三つの独立した状態

| 層         | 状態                                                                 | 所有者                           | 何を決めるか                                 |
| ---------- | -------------------------------------------------------------------- | -------------------------------- | -------------------------------------------- |
| 工程・権限 | フェーズ/ステップ、現在ホスト、採用確定、接続、ドラッグロック        | RoomDO                           | 操作してよい対象と時点                       |
| 基本ツール | 選択 / 手のひら                                                      | 本人のタブ                       | キャンバスのポインター入力の既定解釈         |
| 一時状態   | パン、範囲選択、付箋移動、本文編集、共有プレビュー、投票印、採用待ち | 本人のUI。共有更新の確定はRoomDO | そのジェスチャーまたは工程コマンドだけの解釈 |

選択ツールでも権限のない付箋は動かない。手のひらでも共有/投票/採用が発生しない。ツール切替そのものは工程・票・可視性を変えない。選択と採用は別概念である。

### 2.2 最小限の画面構成

左下の既存キャンバス操作エリアに「選択」「手のひら」の小さい2項目切替を置く。アクティブ状態を形とラベル/アクセシブル名で示し、短いtooltipに有効なショートカットを載せる。ズーム/全体表示は同じ領域にまとめ、付箋の色・文字サイズは選択に従う既存の文脈操作として残す。工程の主要操作は既存の右上/下中央へ保つ。常設の採用・投票・共有・ペンボタンを基本ツールに増やさない。

ボードが主役で、ツール切替により付箋やHUDを押し動かさない。1280×720で主要操作・進行・タイマーと重ならない。狭い画面で省略する場合も現在のツールと切替入口を残す。

### 2.3 用語

- 選択集合: 本人の画面で対象とする付箋ID集合。共有されず、共有権限にもならない。
- 主対象: 単一選択の付箋。複数選択時は本文編集・候補整理など1枚の操作を自動的に代表へ適用しない。
- 空白: 付箋、入力欄、ボタン、HUD、マイ付箋パネル等の操作面ではないキャンバス。グループの装飾背景は空白に含む。
- ドラッグ: 同じpointerIdの押下から画面座標で閾値を越えた移動。既存 `contracts/board.ts` の閾値を再利用し、ズーム率で変えない。
- 取消: 未確定のジェスチャーを止めること。既にRoomDOが受理した公開・移動・投票等の巻き戻しとは異なる。
- 非共有へ戻す: 自分の共有付箋をマイ付箋へ戻す可視性変更。候補に戻す（除外状態解除）とは異なる。

## 3. 工程との接続

工程の許可表は[進行仕様の機能対応表](../sprint-flow.md#対応表の読み方)を参照する。ここでは同じ14行の表を再管理せず、入力操作が使用する能力を定義する。

| 能力名                        | 正本の対象・条件                                                                                | この仕様の利用箇所    |
| ----------------------------- | ----------------------------------------------------------------------------------------------- | --------------------- |
| inspect                       | その本人へ配信された付箋の閲覧。共有位置固定中も可                                              | 選択・カメラ          |
| createPrivate / edit / delete | 各工程のマイ付箋・内容編集・既存削除権限。個人の下書きは本人のみ                                | 作成・本文編集・削除  |
| moveShared                    | [共有付箋の移動](../sprint-flow.md#共有付箋の移動と候補整理)。共有/整理/評価/採用前の決定に限定 | 単数・複数移動        |
| share / returnPrivate         | 同じフェーズの共有Step2、本人の付箋のみ                                                         | マイ付箋と共有の境界  |
| group                         | 課題整理1-3だけ。背景ドラッグ権限を意味しない                                                   | グループの再編・命名  |
| vote                          | 投票工程・本人の今回票・共有候補                                                                | 投票印                |
| candidate / decide / advance  | 現在ホスト、対象工程、未確定等の正本条件                                                        | 除外/復帰・採用・進行 |

正本が許す共有移動工程は1-2・1-3・2-2・3-2・3-3・採用前1-5/2-4/3-5。個人作業、投票、採用後、成果公開後、過去フェーズの共有位置は固定する。これは説明用の抜粋で、変更時は進行仕様から確認する。複数選択を追加しても能力を広げない。発表順・交代予告・タイマーは付箋の編集/移動/共有能力を追加制限しない。発表中は聞くというガイドと認可を区別し、発表完了等の進行コマンドは進行仕様に従う。

<a id="ci-mode-001"></a>

### CI-MODE-001 基本ツールと戻り先

- **区分**: v1
- **状態**: idle / select または hand
- **入力**: ツールボタン、背景フォーカスでV/H
- **主体・工程**: 全参加者。閲覧可能な作業キャンバス
- **対象・前提**: 本文編集・モーダル・ジェスチャーの所有中でない
- **結果**: 初回はselect。Hでhand、Vでselect。選択集合とカメラは保つ。状態は本人のタブだけに適用。工程変更で基本ツールを勝手に切り替えない。再読込はselectで始める。
- **取消**: EscapeはCI-IN-003の順序に従う。handのidleではselectへ戻る。
- **失敗**: 不明なキー/IME中は切替しない。ツール切替でサーバー更新しない。
- **同時操作**: 進行変更は一時状態だけを終える。新ツールを押した時に保留中移動を暗黙commitしない。
- **検証**: AT-001: handへ切替→1-2から1-3へ進行してもhand。再読込はselect。

<a id="ci-in-001"></a>

### CI-IN-001 入力の所有者を一つにする

- **区分**: v1
- **状態**: すべて
- **入力**: pointer/key/wheel
- **主体・工程**: 全参加者、すべての表示工程
- **対象・前提**: イベントの対象と既存ジェスチャー所有者を判定
- **結果**: MUST: ①モーダル/入力/IME/ネイティブcontrol ②進行で失効した状態の取消 ③取得済みpointerの所有者 ④明示的な一時パン ⑤hand ⑥select時の投票印/採用待ち ⑦付箋/文脈操作 ⑧空白の選択。1入力を複数の動作へ送らない。実際に処理する時だけpreventDefaultする。
- **取消**: 所有者を解放した同一pointerupを別のclick/採用へ再配送しない。
- **失敗**: UI重なりや無効対象は下の付箋へclick-throughしない。
- **同時操作**: 別pointerは既存ドラッグを奪わない。gesture所有中のV/H・tool切替は受け付けず、予約もしない。
- **検証**: AT-002: Space+付箋dragでパンのみ。採用待ちのdrag終了で採用しない。

<a id="ci-in-002"></a>

### CI-IN-002 押下・クリック・ドラッグを分離する

- **区分**: v1
- **状態**: idle→pressed→dragging
- **入力**: 主ボタンpointerdown/move/up
- **主体・工程**: 対象能力が許可された参加者
- **対象・前提**: 最上面のヒット対象、同じpointerId
- **結果**: 押下時に起点/対象/修飾キーを固定。閾値未満はclick、閾値以上はdrag。dragが始まったらclick/edit/vote/adoptを抑制。ヒット判定は実寸の付箋境界で、影・操作overlayを含めない。
- **取消**: pointercancel/lost capture/blurは共通取消。
- **失敗**: 権限のないdragはmoveを送らず、drag相当の動きをclickへ落とさない。
- **同時操作**: pointerdown後の新規付箋やz順更新で対象をすり替えない。
- **検証**: AT-003: 25%/100%/200%で同じ画面移動量が同じdrag判定。

<a id="ci-in-003"></a>

### CI-IN-003 Escapeの一段取消

- **区分**: v1
- **状態**: 内側の一時状態から外側へ
- **入力**: Escape
- **主体・工程**: 全参加者
- **対象・前提**: IME変換確定/取消はIMEを優先
- **結果**: MUST: IME→dialog/menu→本文編集終了→active drag/marquee取消→投票印/採用待ち解除→選択解除→handをselectへ、のうち最初に該当する1段だけ実行。説明ガイド等独立UIがfocusを持つ時はそのUIの契約を優先。
- **取消**: 編集終了は保存済み本文を元に戻すUndoではない。drag取消後も選択は保つ。
- **失敗**: 無関係な入力値、票、採用、公開状態を一括リセットしない。
- **同時操作**: 工程変更により既に失効した一時状態は復活させない。
- **検証**: AT-004: 編集中のEscape1回で編集だけ終了、2回目で選択解除。

<a id="ci-sel-001"></a>

### CI-SEL-001 単一選択と読み取り

- **区分**: v1
- **状態**: select / idle
- **入力**: 付箋click、Tab+Enterによる対象化
- **主体・工程**: inspect可能な参加者、全工程
- **対象・前提**: 本人に見える付箋1枚。privateとsharedの選択は混在させない
- **結果**: 非選択の付箋clickで単一選択へ置換。A選択中にTabでBへfocusが移っても集合は変えないが、BでEnterを押すとBを単一選択へ置換する。この1回では編集しない。文字/Deleteはfocusと単一選択が同じ時だけ発火し、違う時はBを選択するだけで文字追加/削除しない。見た目と読み上げで選択を示す。権限のない本文/移動でも読むための選択は可。空白clickで解除。カメラ操作/タイマー/Tab移動だけでは解除しない。
- **取消**: Escapeで解除。削除/非共有化等で見えなくなったIDは取り除く。
- **失敗**: 選択しただけで編集・採用・投票・共有を行わない。直接の単一clickによる既存前面化はCI-NOTE-003として区別する。
- **同時操作**: 他者の選択を同期しない。他者移動しても同じ可視IDは選択を保つ。
- **検証**: AT-005: 候補外付箋を一般参加者が選ぶと読みやすくなるが復帰権限は増えない。

<a id="ci-sel-002"></a>

### CI-SEL-002 複数選択と範囲選択

- **区分**: v1
- **状態**: select / idle、工程コマンド未armed
- **入力**: Shift+click、空白主ボタンdrag、Shift+空白drag
- **主体・工程**: inspect可能な参加者
- **対象・前提**: 現在フェーズの可視shared付箋。privateパネル/過去フェーズ/操作overlayは除く
- **結果**: 空白dragで矩形と接触した付箋を選ぶ（境界接触を含む、方向に依存しない）。通常矩形は集合置換、Shift矩形は押下時集合への和集合。Shift+clickは1枚をtoggle。候補外も選択可。隠れた付箋は描画されていて矩形と交わるなら対象、配信されないものは対象外。
- **取消**: Escape/取消で押下前集合へ戻る。空矩形の通常確定は空集合、Shiftなら元集合。
- **失敗**: 権限が混じっても勝手に移動可の一部だけを動かさない。範囲内のボタンを発火しない。
- **同時操作**: 候補IDをpointerdown時に固定し、up時に不可視となったIDを除く。交差判定はup時の現在描画境界で行い、ハイライトと一致させる。他者移動/本文伸長を現在境界へ反映し、途中追加は次回選択対象。
- **検証**: AT-006: A/Bに接触する矩形でA/B。ShiftでC追加、Shift+BでBだけ解除。

<a id="ci-sel-003"></a>

### CI-SEL-003 複数選択の操作範囲

- **区分**: v1
- **状態**: 選択数2以上
- **入力**: 選択付箋drag、単一付箋click
- **主体・工程**: moveSharedの能力に従う
- **対象・前提**: 同一フェーズ/sharedのみ
- **結果**: v1の一括操作は移動のみ。選択済み付箋のクリックだけはその1枚へ縮小、dragなら押下時集合を維持して相対移動。未選択Cをdragした場合はC単一へ置換してCを動かす。Shiftによるtoggleはclick確定時だけ実行し、Shift+dragではtoggleせず、選択済みなら集合・未選択ならその1枚を移動。単一本文編集・色/文字サイズ・削除・共有・非共有化・候補整理・採用・投票の一括入口は出さない。
- **取消**: 空白click/Escapeで全解除。Shiftで残り1枚なら単一操作へ戻る。
- **失敗**: 複数の中の先頭/最後へ単一操作を暗黙適用しない。
- **同時操作**: 削除/不可視化で集合が1枚になった場合のみ通常単一状態へ移る。
- **検証**: AT-007: 3枚選択中Delete/文字入力/候補外ボタンは一括変更せず、dragだけ3枚を動かす。

<a id="ci-pan-001"></a>

### CI-PAN-001 画面移動

- **区分**: v1
- **状態**: hand、または一時パン
- **入力**: handで主drag、Space保持+主drag、中ボタンdrag
- **主体・工程**: 全参加者、閲覧できるキャンバス
- **対象・前提**: キャンバス面。入力欄・モーダル・マイ付箋パネル・HUDは除く
- **結果**: 押下時カメラ+画面差分だけを更新。付箋上からもパン可。open-hand/grabbingを示す。Spaceは一時上書き、解除後は元基本ツール。選択/投票印/採用待ちは保つ。
- **取消**: pointerup/Space解除/blurで一時パンを終え、最後に描画したカメラ位置を維持。
- **失敗**: panは付箋移動や共有ではない。右ボタンは文脈メニューに残す。
- **同時操作**: 付箋drag中に後からSpaceを押してもpanへ乗換えない。
- **検証**: AT-008: 選択付箋上Space+drag後、付箋座標不変、カメラのみ変更、Space解除でselect。

<a id="ci-pan-002"></a>

### CI-PAN-002 ズーム・スクロール・全体表示

- **区分**: v1
- **状態**: idle
- **入力**: wheel、trackpad、ズーム/100%/全体表示ボタン
- **主体・工程**: 全参加者
- **対象・前提**: キャンバス上。内側にスクロール対象がある時はその対象を優先
- **結果**: 通常wheel/2指scrollはpan。Shift+縦wheelは水平だけpan。Ctrl/Meta+wheelまたはブラウザが同形式で通知するpinchはポインター中心zoom。ボタンzoomは作業可能領域中央。上下限は既存camera定数。全体表示はHUDを避け現在の可視付箋を含める。2軸マップはmapと付箋双方を含める。
- **取消**: 操作取消は不要。100%はzoomだけ、全体表示は明示操作のみ。
- **失敗**: window全体のブラウザzoomを奪わない。空ボードの全体表示は既定カメラ。
- **同時操作**: active drag/marquee中のwheel-camera変更はv1では受け付けず、座標系を固定。他者操作で自動fitしない。
- **検証**: AT-009: Shift+wheelでy不変。共有/再投票ループや他者追加で本人カメラをリセットしない。

<a id="ci-note-001"></a>

### CI-NOTE-001 付箋の作成・本文編集

- **区分**: inherited
- **状態**: selectで本人private作業、またはfocusと単一選択が一致しedit可能
- **入力**: 既存作成入口、選択済みclick、Enter、印字文字
- **主体・工程**: 既存createPrivate/edit能力のみ
- **対象・前提**: 1枚。本文editorがfocusを持つ時は通常の文字編集
- **結果**: 作成はprivate領域のみ。最初clickは選択、次click/Enter/印字文字で本文編集。印字文字は既存本文末尾へ1文字だけ入れる。V/Hも付箋focusなら文字入力でありツール変更しない。2000文字、全文が見える可変高、色/文字サイズの既存要件を維持。
- **取消**: Escapeで編集終了。IME中Escapeは変換を優先。blurは既存autosaveを継続。
- **失敗**: 保存失敗を成功表示しない。未送信本文を保持して再試行可能にする。
- **同時操作**: 他者編集/工程進行で上書き可能性がある時は最新server状態とローカル未送信を区別し、本文を無言で破棄しない。
- **検証**: AT-010: 選択付箋にh→末尾h、本文編集欄にSpace→空白。どちらもカメラ不変。

<a id="ci-note-002"></a>

### CI-NOTE-002 削除キーと安全な対象

- **区分**: v1
- **状態**: 単一選択とfocusが一致・editor外
- **入力**: Delete、明示削除操作（Mac前方削除はFn+Delete）
- **主体・工程**: 既存delete能力のみ
- **対象・前提**: 自分のprivate付箋1枚。共有済みの削除権限を新設しない
- **結果**: Deleteは許可対象のみ削除。Backspaceはeditor外で付箋丸ごと削除に使わない。editor内のDelete/Backspaceは文字編集。削除済み対象へのfocusは近接付箋/作成入口へ戻す。
- **取消**: 取消やUndoの新機能はこの仕様で追加しない。既存確認/復元契約に従う。

### CI-SYNC-002 共有状態の認可と競合

- **区分**: v1

- **検証**: AT-022: Aが1枚drag中にBがそれを含む3枚drag→Bは0枚開始。切断後もprivacy境界を越えない。

- **失敗**: 他者シール/候補外/phase違い/通信失敗で票を失わない。
- **同時操作**: pointer ID、pending request、phase版を照合し重複pointerupで二重投票しない。
- **検証**: AT-027: 配置済み票を空白へdrop→元票保持、paletteへdrop→その1票だけ回復。

### CI-MAP-001 評価座標とカメラを分離する

- **区分**: v1
- **状態**: phase3 map表示中
- **入力**: 付箋drag、ホストのmapサイズ操作、本人zoom
- **主体・工程**: moveSharedは3-2/3-3/採用前3-5。mapサイズ変更は既存ホスト能力
- **対象・前提**: 横=実現可能性、縦=価値、左下0/0・右上100/100
- **結果**: 評価座標は0..100の共有値、camera zoomは本人表示、mapサイズlevelは共有表示を分ける。軸編集/入替は追加しない。3-4は位置固定。複数moveのclampはCI-MOVE-002。
- **取消**: 再投票/候補復帰で評価位置を昔へ戻さない。
- **失敗**: 世界pxと評価%を混ぜて位置保存しない。
- **同時操作**: mapサイズ変更中のdragはそのジェスチャーを取り消し、最後の受理評価値で再描画して再操作を案内。
- **検証**: AT-028: 自分のzoomを変えても他者の評価値不変、mapサイズ変更でも各付箋の0..100値を保つ。

<a id="ci-hist-001"></a>

### CI-HIST-001 移動のUndo / Redo

- **区分**: v1
- **状態**: editor外、移動履歴あり、処理待ちでない
- **入力**: Windows/Linux Ctrl+Z / Ctrl+Shift+Z、macOS Cmd+Z / Cmd+Shift+Z、画面の戻す/やり直す
- **主体・工程**: 元操作の本人、現在も対象全件のmoveShared能力がある
- **対象・前提**: 本人タブ・同room・同phase/工程訪問の、成功確認済み単一/複数の移動履歴
- **結果**: v1は共有付箋の座標移動（通常ボードと2軸評価map）だけ。マイ付箋内の並べ替えは含めない。UIは「移動を元に戻す」「移動をやり直す」と明示し、次の対象/枚数と不可理由をtooltip/アクセシブル名に示す。1drag=1履歴、複数は1履歴。zero delta/拒否/未送信previewは履歴なし。Undo成功後だけRedoへ、Redo成功後だけUndoへ。成功した本人inverseのreceiptに限り履歴cursorと連続する本人履歴の期待版を追随させ、2段以上のUndo/Redoを可能にする。peer更新や結果不明の要求では期待版を更新しない。新規の成功移動でRedoを破棄。連打は1要求pending中無効。
- **取消**: Escapeは履歴を実行しない。pointerup前dragはpreview破棄/履歴なし。送信後はpending解決を待ち、成功なら別入力でUndoする。
- **失敗**: 本文editor/IMEはnative Undo優先。共有/非共有化・作成/削除・本文/色/文字サイズ・投票・採用・工程/host・mapサイズ・既存候補整理は対象外。該当操作後に単に「元に戻す」と通知せず対象外と説明。
- **同時操作**: 履歴はserver成功のoperation ID・開始/終了位置・対象ID・位置/可視性/関連group版を持つ。他者変更や対象lockがあればCI-HIST-002。phase移行/採用確定/切断後の再接続/再読込で履歴を終了し復活させない。
- **検証**: AT-030: A/B/Cの移動1回→Undo1回で3枚同時復帰→Redo1回で3枚同時再移動。同じ付箋P0→P1→P2後Undo2回でP0、Redo2回でP2。editor Ctrl+Zは本文だけ。

<a id="ci-hist-002"></a>

### CI-HIST-002 逆操作も現在の権限で原子的に検証する

- **区分**: v1
- **状態**: UndoまたはRedo送信前/受理時
- **入力**: 履歴IDを指定した逆操作
- **主体・工程**: 元操作の本人。現在hostかどうかはmove権限の代用にしない
- **対象・前提**: 位置/visibility/関連group版が履歴の期待値と一致し、全対象存在・ロック取得可
- **結果**: RoomDOが全対象を検証し1transactionで逆操作/履歴確定。1-3では位置に加え元移動のgroup所属・消滅/分裂したgroup ID/nameも履歴に含め、安全に全部復帰できる時だけ成功。他phaseの座標/票/他者本文を上書きしない。inverse失敗で部分復帰しない。Undo/Redoは最新stackOrderを保持して新しい前面化を起こさない。通常note:moveの再送で代用しない。位置競合は専用の単調増加position revisionで検出し、座標がA→B→Aへ戻ったABAも見逃さない。本文/票/fontの更新時刻を位置版の代用にしない。
- **取消**: 確認前に取消しても既に受理した逆操作は取消済みと偽らない。結果を照会。
- **失敗**: 期待版不一致は「ほかの人の変更があるため、この移動は戻せません」。当該履歴を無効表示し、同じキー入力で古い別履歴へ飛ばない。公開後は他人が見た事実を戻せないためvisibility操作を履歴へ入れない。
- **同時操作**: remote更新で影響した履歴だけを無効化。対象外の本人の確定board操作（作成/削除/共有/非共有化/本文保存/表示属性/候補整理/投票等）は移動履歴の境界となり、Undo/Redoの遡及を止める。次の新規移動から新しい履歴を始める。native editor内のUndoは独立。候補外専用Undoは別入口「候補に戻す」で、Ctrl/Meta+Zへ接続せず最新候補操作だけを戻す。
- **検証**: AT-031: Aが3枚移動→Bが1枚移動→AがUndoで0枚復帰。1-3のgroup名消滅後Undoは元の名と所属も戻るか全拒否。

<a id="ci-perf-001"></a>

### CI-PERF-001 ドラッグ開始の即応性を守る

- **区分**: v1
- **状態**: pointerdown→閾値超過→local preview→server受理
- **入力**: mouse/trackpadによる単一/複数/shared/private drag
- **主体・工程**: 既存能力・lockを尊重
- **対象・前提**: 描画開始と永続化/認可の完了を別の計測点にする
- **結果**: MUST: 許可が見込める対象は閾値を越えた次の描画frameを目標に本人previewを追従させ、認可ACK/公開commitを待って視覚開始しない。未受理previewは共有済み/保存済みとは表示しない。初期座標/カメラ/必要な領域矩形は読み取りをまとめ、frame内でread/write反復や全付箋の繰返し計測をしない。
- **取消**: 拒否/取消はpreviewを除いて最新受理状態へ。private previewを他者へ送らない。
- **失敗**: ネットワーク待ちで掴んだ付箋が無反応なままにならない。計測が遅れた時も非公開領域を推測してpublishしない。
- **同時操作**: 複数選択は対象ID/起点座標を開始時に固定、領域geometryはviewport/visual viewportのresize・pan/zoom・パネル開閉/位置・tray scroll・付箋追加/削除/順序/本文/font/高さ変更でinvalidateしてまとめて更新。moveはframeごとに最大1描画、共有通信頻度とは独立。
- **検証**: AT-032（暫定設計目標・未実測/数値合意前）: 60Hz代表PC・100枚（長文混在の比較fixture）・zoom25/100/200%・RTT0/150/500ms各30dragで、閾値超過→初回previewのp95<=50ms、開始に起因する50ms超long taskなしを暫定目安とする。60Hzの1frame≈16.7msに対し視覚開始を次frameへ寄せ、50ms≈3framesを検出上限の初期案とした設計上の選択で、業界の合否基準/現達成値ではない。実機baselineの端末/OS/browser/CPU/負荷/commitと実測値を記録し、この数値と負荷条件をレビューしてからリリース合否値を確定する。

## 5. 意図的に含めないもの

自由な図形、コネクタ、汎用描画、無制限のオブジェクト種、移動以外を横断する汎用Undo/Redo、複数一括削除/共有/非共有化/候補整理/採用、グループ背景からの一括drag、右dragパン、モバイルの新しいgesture体系はv1の対象外。将来ペンの存在を理由に現在の工程権限や保存モデルを広げない。

ドラッグ以外の共有入口は今回追加しない。キーボードだけで共有を完結できない制約は残るため、アクセシビリティ適合済みとは主張しない。代替操作を作る場合は既存drag-only要求との整合を明示して別途判断する。

## 6. 実装と検証の順序

1. 影響する規則IDとAT-IDをIssueから参照する。全文を複製せず、変更する契約をこのMarkdownで更新する。工程権限を変える場合は進行仕様も同じPRで更新する。
2. 選択/handとfocus・入力所有者を導入し、start/preview/cancel/commit、操作ID、位置・group期待版をcontracts→RoomDO→UIの順に実装する。旧クライアント混在時のprotocol互換と機能gateは実装PRで設計する。
3. drop-only共有と即応previewを接続し、能力の否定系・pointer cancel/blur・非公開性・host交代・通信遅延/ACK喪失・二者同時操作を失敗するテストから確認する。
4. 移動Undo/Redoを接続する。1-3のgroup ID/name/所属を原子的に復帰できない段階はUndoを無効表示し理由を示す。AT-031を満たすまでv1完了とはしない。
5. ATの状態へ実際に到達し、1280×720/狭い画面、25/100/200%zoom、日本語IME、Mac/Windows、mouse/trackpadを確認する。AT-032の数値は暫定設計目標で、実機baselineとレビュー後に合否値を確定する。
6. 各実装Issueの完了条件として人による操作確認を行い、空白dragの意図、Select/Handの認知、複数移動、共有の境界理解を確認する。自動テストや図の作成をユーザビリティ検証と呼ばない。

作成/削除のUndoは次段階で、復活時のprivate可視性・本文・group/票の参照・同じIDの再利用防止を設計する。色/文字サイズ・private並べ替えも独立拡張。共有は他人の閲覧を取り消せないため「共有は元に戻せません。自分の付箋をマイ付箋へ戻す操作はできます（共有Step2のみ）」と説明する。

### #523の移動transaction契約

- 新Workerはsnapshotの`moveProtocolVersion: 1`で対応を宣言する。新UIは対応Workerで共有移動を`note:move:start / preview / cancel / commit / status`へ切り替える。旧Workerでは単一の旧dragだけを互換利用し、複数移動を開始しない。旧clientのstreaming保存・private共有/戻しは移動transactionの保証対象外で、drop-only共有は#524に残る。
- startはUUIDのoperation ID、phase訪問版、座標系、group/map版、固定対象全件のposition/visibility版を受ける。最大256枚、開始はuserごとに1分60件まで。非member・private・別phase・重複ID・新旧lock競合・専用版の不一致で全件拒否する。不可視な対象IDや本文は拒否理由に含めない。
- 本人previewはstart ACKに依存せず、押下時offsetと集合deltaを保ってframeごと最大1回描画する。previewは確定位置・分類・版を保存せず、peer previewは配信しない。名前付きcursorの移動表示は全対象のlock・所有接続・工程・可視性・版を検証して配信し、取消/確定/lease期限/切断/除外で解除する。mapのlock表示も開始と終了に追随する。mapでは全集合のdeltaを0..100へclampする。表示は全付箋の中心に共通の線形有効域（平面幅から付箋幅、平面高から共通最大表示高を除いた域）を使い、端でも集合の相対距離を保つ。同じ域でpointer入力を逆変換する。長文は本文を保持したまま表示高を平面高の75%までに収め、長文1枚で短い付箋も移動不能にしない。通常canvasのdelta境界は有効位置の両端間である±2×座標上限とする。
- pointerupだけがcommitを送る。RoomDOは現在のmember/工程/採用/可視性/専用版/lockを再検査し、位置・相対stack順・既存分類再編・成功receiptを1回のtransactionSyncで保存する。失敗時は全位置とgroupが戻り、確定後だけ受信者別の`notes:moved`を配信する。旧client向けに確定note/groupイベントも配る。
- 確定送信前のEscape・window blur・pointercancel・所有capture喪失はgestureとpreviewを破棄し最新確定状態へ戻る。NoteCardからscrollerへの通常capture移管は取消と扱わない。閾値前の押下もEscape/blurで破棄する。送信後は結果照会だけを2秒間隔で続け、遅延start ACK・Escape・切断・送信後errorをcommit再送や成功/失敗の断定に使わない。error応答への即時再照会は行わない。再接続もドラッグを再開せず本人のoperation結果を照会する。閉鎖後もmember本人のread-only結果照会を受理し、期限後はexpired、操作削除後または非memberには内容を含まないunknownで終端にする。
- position/visibility版は専用SQL triggerで単調増加し、旧clientの更新とABAも検知する。group/map版は変更イベントとsnapshotで追随する。receiptは移動前後の位置・専用版、実際に変更したgroup ID/name/所属の前後、削除したgroupの非移動メンバーを含む全影響対象の専用版を持ち、本文/作者/票を持たない。receiptは24時間保持し、その後はIDの墓標だけをルーム削除まで残して古い要求をfail-closedにする。snapshot/batch/新move由来の旧group配信は同じ現在工程と全メンバー可視性で投影する。無関係な分類はreceiptへ含めず、不可視な分類を実際に変更する操作は位置を含めて全拒否する。非共有化/削除で残った旧分類は除去する（1-3の既存再編では元分類情報を保持する）。過去receiptも返信時に全影響対象の現在可視性を再検査し、1件でも不可視なら成功statusだけを返してreceipt全体を伏せる。成功を失敗に変えず、UIは古い逆操作情報も破棄する。
- \#522の選択入口が渡す`selectedNoteIds`との統合は別Issueの依存であり、本実装はhook境界と100枚・長文混在の固定3枚集合storyを持つ。#525のUndo/Redo本体は未実装。実機・Mac/Windows・trackpad・日本語IME・人による操作確認、および性能の最終合否は未確認として残す。

通信と永続化の判断は[ADR 0006](../../adr/0006-move-transactions.md)、性能の測定条件と制約は[2026-10-04の性能計測](../../archive/canvas-move-performance-2026-10-04.md)を参照する。
