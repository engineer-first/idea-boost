# CodeRabbitのレビュー運用

完成した差分へレビュー枠を使うため、実装中はDraftを維持し、Ready時に初回、
修正をまとめた後に手動増分レビューを要求する。設定の正本は
[.coderabbit.yaml](../../.coderabbit.yaml)。日本語レビュー・自動初回・Draft除外を維持し、
`reviews.auto_review.auto_incremental_review: false` で後続pushの自動レビューを止める。
既存CIと人の最終判断は継続する。

読む対象はPR作者・レビュー担当。レビューの開始条件やCodeRabbitの制限仕様を
変更したときに更新する。実repoでの確認結果と未確認事項は
[Issue #419](https://github.com/engineer-first/idea-boost/issues/419)へ記録する。

## レビューを要求するタイミング

| 状況                      | 操作・確認                                                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実装中                    | Draftを維持し、既存CIと実装担当から分けたレビューで確認する。Draft中に手動要求するとレビューを実行できるため、通常は要求しない。                   |
| 初回レビュー              | 実装・検証をまとめてReadyにする。最初から通常PRで作成すると、その作成が初回レビューの機会になる。                                                  |
| Ready後も初回が始まらない | botのスキップ理由と実効設定・残枠を確認し、レビューが未開始ならPRへ `@coderabbitai full review` をコメントする。すでに進行中なら重ねて要求しない。 |
| 初回後の修正中            | 途中pushでは自動増分レビューしない。指摘への修正と検証をまとめる。                                                                                 |
| 修正・検証が揃った        | PRへ `@coderabbitai review` をコメントし、前回以降の差分を増分レビューする。                                                                       |
| 全体を読み直す必要がある  | 大幅な設計変更など、理由がある場合だけ `@coderabbitai full review` を使う。                                                                        |
| マージ前                  | 下記の手順で最新headまでのレビュー完了とCIの結果を確認する。                                                                                       |

公開repo・OSS等の適用条件によって、自動初回が使えない場合がある。
公式仕様ではスター10未満の公開repoは手動要求の対象とされているため、
Readyへの切り替えだけで開始したと決めつけない。
初回の開始を確認してから修正へ進み、実行中に追加pushして対象headを変えない。
レビューが新pushで差し替えられると、結果が届かなくても先の枠を消費する場合がある。

`review` と `full review` はどちらも実行時にレビュー枠を使う。
通常の修正は増分にまとめる。自動増分を再開するための `resume` を
通常の再レビュー要求の代わりに使わない。

## 枠不足と実効設定を確認する

- PRへ `@coderabbitai rate limit` をコメントし、現在の残枠と次に利用可能になる時刻を確認する。この照会はレビュー枠を消費しない。
- 利用可能になるまでは修正とCI確認をまとめ、利用可能になってから `@coderabbitai review` を要求する。待っただけでレビューが完了したとは扱わない。
- `@coderabbitai configuration` の応答で設定値と由来を確認する。Repository YAML、継承設定、UI設定、既定値を区別し、応答が示すブランチや設定対象も確認する。base由来の応答だけで未マージの変更が適用済みとは判断しない。
- 管理者はPR作者のseat割当とReview Usageを確認する。過去のseat未割当によるOSS枠適用と、直近利用量によるFair Usage制限を分けて調べる。プラン名だけから実効枠を推測しない。
- seat未割当なら、時間を待っても割当状態は変わらない。seat・契約・課金の変更は別途判断する。情報を参照できない場合は、確認できた応答と不明点をIssueへ記録する。

レビュー制御後も不足する場合は、Review Usageのレビュー回数・待ち時間・
未レビューhead、有効な指摘、必要な追加操作を確認して、課金や別手段の併用を判断する。
この運用変更では契約・seat・課金設定、新しい接続を変更しない。

## 最新headのレビュー完了を確認する

1. PRの最新head SHAを取得する。CLIでは `gh pr view <番号> --json headRefOid --jq .headRefOid` を使える。
2. CodeRabbitのレビュー記録の対象コミット・完了状態を確認し、最新headまで対象になっているか照合する。増分なら前回レビューから最新headまでの差分が確認されたことを確かめる。
3. 進行中・スキップ・枠不足、またはレビュー対象より新しいpushがある場合は未レビューとして扱う。必要な修正をまとめ、枠を確認して再要求する。
4. 最新headのCIと必要なレビューを確認したうえで、人がマージを判断する。

CodeRabbitは枠不足時にもpassing checkを出し、過去のapprovalを維持する仕様。
緑のcheck、以前のapproval、指摘0件だけでは最新headのレビュー完了を証明できない。

## 設定変更後に実repoで確認する

静的なYAML検証は、外部サービスの発火やseat割当を保証しない。
通常の実装PRで次の結果を記録し、検証だけの不要なレビュー要求を増やさない。

- Draft中のpushで自動レビューが始まらない。
- Readyで初回が始まるか、スキップ理由を確認して手動初回が完了する。
- 初回後の修正pushで自動増分が始まらない。
- 修正をまとめた手動増分が完了し、対象が最新headと一致する。
- 変更後の実効設定で、日本語・自動初回有効・Draft除外・自動増分無効を確認する。

確認対象のPR・head SHA・実効設定の応答・レビュー結果をIssueへ記録する。
確認できない項目は未確認のまま残し、設定PRを作っただけでIssueを完了にしない。

## 設定を戻す

この変更を戻す場合は、`.coderabbit.yaml` に追加した `reviews.auto_review` の
3項目（`enabled`、`drafts`、`auto_incremental_review`）を削除し、
`language: "ja-JP"` を残す。戻す前に実効設定を確認し、その後に追加された設定は保持する。
戻した後も `@coderabbitai configuration` で実効設定を確認する。
既定では自動増分が有効になるため、途中pushによるレビュー消費が再開する。
