# 一次情報を先に残すIssueの例

読者: Idea Boost の記録運用をレビューするチーム。Issue、Type、本文、コメントを使う人向けの例です。

以下の6件は架空の例です。GitHubへ実際に起票しません。本文は対象を示す入口にし、まず一次情報をコメントに残します。要約・分析・判断は必要な場合だけ後続コメントに書きます。コメント番号は役割を示す例で、実際のURLや投稿済みのコメントを意味しません。

## フィードバック例1

タイトル: `2026-10-20のフィードバック`\
Type: フィードバック

| 場所                    | 内容                                                                                                                                                                     |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本文                    | **対象:** 2026-10-20実施分のアプリ内フィードバックとアンケート回答。                                                                                                     |
| コメント1: 一次情報     | アプリの受付ID sample-01「グループ化した付箋をまとめて動かしたい」。受付ID sample-02「他の人の票が見えないのがよかった」。取得日時は2026-10-20 18:00、対象は当日の投稿。 |
| コメント2: 必要なら判断 | グループ移動の要望を既存の改善Issueと照合する。投票への好評は原文として残す。採用や改善完了は未判断。                                                                    |

## フィードバック例2

タイトル: `2026-10-21のフィードバック`\
Type: フィードバック

| 場所                         | 内容                                                                                                                                                                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本文                         | **対象:** 2026-10-21の授業で得たフィードバック。                                                                                                                                                                                                 |
| コメント1: 一次情報          | アンケートのサンプルシート・タブ1・行5「問いに何を書けばいいか迷った」。行6「タイマーに気づかなかった」。元セルの架空URLは <https://example.com/sheet?tab=1&cell=M5> と <https://example.com/sheet?tab=1&cell=M6> 。取得日時は2026-10-21 18:00。 |
| 後続コメント: 追加の一次情報 | 翌日に見つかった同じ10月21日実施分の回答を、元の行・セルと取得日時を添えてこのIssueに追記する。取得日が変わっても別Issueを作らない。                                                                                                             |

要約をまだ作っていなくても、起票と原文の保存を進めます。同じ日の投稿・回答ごとにIssueを分けません。

## 競合調査例1

タイトル: `競合Aの入力中に出るヒントを調べる`\
Type: 競合調査

| 場所                    | 内容                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本文                    | **目的:** ヒントの文言と表示場面を調べる。 **対象:** 競合Aの入力画面を2026-10-20に調査する。                                                                 |
| コメント1: 一次情報     | 2026-10-20 10:00、架空URL <https://example.com/competitor-a> で入力欄を開くと「まずは1つ書いてみましょう」と表示された。操作と画像を添付。表示原因は未確認。 |
| コメント2: 必要なら分析 | 初回入力の案内として参考になる。現時点で自分たちの製品へ採用したわけではない。                                                                               |

## 競合調査例2

タイトル: `競合Bの投票から結果表示までを調べる`\
Type: 競合調査

| 場所                         | 内容                                                                                                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本文                         | **目的:** 投票中の参加者への案内を知る。 **対象:** 競合Bの投票画面から結果画面まで。                                                                              |
| コメント1: 一次情報          | 2026-10-21 10:00、架空URL <https://example.com/competitor-b> で投票開始を押すと残り票数が表示された。投票中の他者の票は見えなかった。操作・画像・確認条件を添付。 |
| 後続コメント: 追加の一次情報 | 途中参加したときの表示を後日確認した結果を、観察日時と証拠付きで追加する。                                                                                        |

現在の状況欄や要約を本文へ作りません。作業中の既存Issueがある場合は、その調査を維持します。

## 成果データ例1

タイトル: `2026-10-20の成果データ一覧`\
Type: 成果データ

| 場所                    | 内容                                                                                                                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本文                    | **対象:** 2026-10-20の実施で得られた成果データ一覧。                                                                                                                                                                                             |
| コメント1: 一次情報     | **ルームA:** 課題「授業中に質問しづらい」、問い「どうすれば、ためらわず質問できるか」、決定した案「匿名で質問を集める」。元データID sample-a、15:00保存、18:00取得。架空URL <https://example.com/outcomes/sample-a> 。元データと共有盤面を添付。 |
| コメント2: 別の一次情報 | **ルームB:** 課題「作業の進み具合が分からない」。問いを考える工程までの途中記録。元データID sample-b、16:00保存、18:00取得。架空URL <https://example.com/outcomes/sample-b> 。未決定の案を補完しない。                                           |
| コメント3: 必要なら分析 | 各成果を見比べて気づいたことを、元のコメントを示して記録する。案が決まったことと実際に効果があったことを区別する。                                                                                                                               |

## 成果データ例2

タイトル: `2026-10-21の成果データ一覧`\
Type: 成果データ

| 場所                      | 内容                                                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本文                      | **対象:** 2026-10-21のワークショップで得た成果データ一覧。                                                                                                                                                  |
| コメント1: 一次情報       | **チーム別の成果一覧:** 元データID sample-team-results の表を添付。対象は当日の実施分、取得日時は2026-10-21 18:00。架空URL <https://example.com/results/sample-team-results> 。元の表の列名と値を保持する。 |
| コメント2: 追加の一次情報 | **実施全体の提出物:** 元データID sample-outputs のファイル一覧を添付。架空URL <https://example.com/results/sample-outputs> 。どのチームに対応するか不明なものは不明のままにする。                           |

成果データをルーム単位に限定しません。日付・実施回の一覧Issueへ、元データのまとまりに応じたコメントを追加します。

## AIが起票するとき

フィードバックと成果データは、先に同じ対象日・実施回の既存一覧を検索し、あればそこへコメントします。新しい一覧が必要なときだけ、最小限の本文で起票して一次情報を追加します。要約・判断はその後の任意の作業です。フォームはGUIの入力支援であり、AIがCLI・APIで作る場合も[共通ルール](evidence-issues.md)を読みます。
