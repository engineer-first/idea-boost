PRの版を開いて確認する

月間の撮影枠を使い切るとUI Testsが保留になっていました。実アプリの操作は既存のPreview URLで確認し、状態別の画面は公開Storybookで確認します。

PRへpushする

そのコミットのコードからStorybookと構成図をビルドします。依存更新botのブランチは公開を省略します。

Storybookを公開する

Chromaticへアップロードします。公開先と閲覧権限は従来の設定を使います。

PRから開く

チェック欄のStorybook Publishを開き、対象コミットと公開ビルドの対応を確認します。

状態を選んで見る

状態別のstoryと構成図を開き、表示や操作を確認します。

  • 状態別の画面：loading / empty / success / errorなどのstoryを選びます。例：Home / HomeErrorAlert。
  • データ構造：Schema / SchemaDiagramでD1・RoomDOの図、Schema / SchemaDetailsでカラム・インデックス・制約を確認します。
  • コードの依存関係：Dependencies / DependencyDiagramで機能全体や各機能の図を確認します。

SchemaとDependenciesは公開時に同じコミットから生成されます。撮影対象を追跡する設定を外しても、公開される図には変更が反映されます。

撮影停止はプロジェクト設定で行う

Chromaticのプロジェクト管理画面でUI ReviewとVisual tests（GitHub上のUI Tests）の両方をDisabledにします。月間上限によるPausedは無効化とは異なります。

公式のよくある質問では、どちらか一方でも有効なら撮影が続き、両方を無効にすれば撮影を止めて公開を継続できると説明しています。

設定・処理現在の扱い
UI Tests / UI Reviewプロジェクト設定で両方OFF。新しいビルドの撮影実績も確認します。
on: push従来どおり、そのブランチのコミットを公開します。
skiprenovate/**・dependabot/**だけ公開を省略します。全体へのskip: trueは公開も止めるので使いません。
exitOnceUploaded: true公開完了でworkflowを終了します。撮影を止める設定ではありません。
撮影対象の追跡・差分承認撮影対象を絞る設定、図の変更を撮影へ反映する追跡設定、差分の自動承認を外します。Accept / Denyの操作は不要です。

設定の正本は公開workflowです。PRコメントへのStorybookリンク追加や、手動の画像比較ジョブは設けません。

公開成功とテスト成功を区別する

Storybook Publish

その版のStorybookの公開完了を示します。画面比較の合格を示すものではありません。

公開workflowの失敗

ビルドやアップロードが失敗した場合は、公開失敗としてログを調べます。失敗を成功へ読み替える処理は加えません。

過去のUI Tests

過去コミットのpendingは、その時点の検査状況です。新コミットの公開結果とは分けて記録します。新しいビルドでも撮影・保留が続くなら、対象コミットと両設定を確認します。

Vitestのunit・DOM、Worker / RoomDO、browserの操作・レイアウト検査は継続します。browserの寸法・到達性・フォーカス・playの検査は、画像比較の停止後も必要です。

storiesの件数や公開成功だけで、操作・認可・説明の分かりやすさを保証したとは判断しません。見た目は公開Storybook、実アプリの動作はPR Previewを使ってレビューします。
