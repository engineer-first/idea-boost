Idea Boost ドキュメント

アーキテクチャ・設計判断・技術検証に関する解説ページの目次です。

  • Idea Boost — 構成 & デプロイ概観 2つの Cloudflare Worker（app / api）、RoomDO と D1 の責務分担、境界ルール、CI/CD、よく使うコマンドを1ページで俯瞰する。
  • デプロイ構成図 — 本番経路・秘密・release CI ランタイム経路（同一オリジン + service binding）、秘密の置き場所、api → app のデプロイ順、release ブランチの GitHub Actions を図で俯瞰する。
  • Cloudflare の地図 — Workers / Durable Objects / D1 Go + Vue の経験を起点に Cloudflare の3部品を対応表から理解する。「1ルーム = 1 権威サーバー」の設計理由を実コードで辿る技術解説。
  • データはどこに住むのか — D1・RoomDO・contracts の責務マップ なぜ DB を D1 と RoomDO の2つに分けているのか、contracts/ はどこまでの責任を負うのか、PRD の残り機能でデータがどう増えるのかを実コードの根拠つきで解説する。
  • 系統図 — ルーム作成 「ルーム作成」と「ルーム参加」がコード上でどう流れるか。UI → Server Action → api-worker → D1 / RoomDO の境界と招待コードの仕様をコード引用つきで辿る。
  • 技術選定の再評価 — 実装負荷を除外した場合 Cloudflare Workers + Durable Objects を選んだ意思決定メモ。コスト試算・候補比較・判断が反転する条件の記録。
  • HTTPしか知らない人のための Supabase Realtime 今回の付箋アプリで新しかった WebSocket の部分を、知っている HTTP との差分だけで理解する技術解説。
  • PoC実装の現在地 — リアルタイム付箋同期 poc-realtime-note-sync ブランチの実装マップ。データの流れ2経路と、25ファイルの4層構成を1ページで俯瞰する。
  • 影は、下にしか落ちない — 付箋UI/UXの熱弁 tldraw から移植した付箋インタラクションの解説。下方向だけの影、選択の青い枠、1クリック3つの意味。触れるデモ付き。
  • 付箋ボードを tldraw ではなく自前実装にした理由 付箋を「絵」ではなく「行」として扱う設計判断の記録。dnd-kit すら使わなかった理由と、tldraw から移植した UX。ドラッグできるデモ付き。
  • Visual Regression Testing 運用ガイド VRT とは何か、Chromatic がこのリポジトリでどう動くか、PR で何をすればよいか。差分デモ付きのチーム向けリファレンス。
