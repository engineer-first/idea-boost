# 開発サーバーの起動と停止

AIエージェントが複数のworktreeで並行開発すると、検証後の開発サーバーが残り、CPU・メモリを消費し続ける。通常の起動を2時間で停止することで停止漏れを減らし、継続利用する環境は明示的な常駐コマンドで残す。

この文書は起動コマンド、停止する範囲、利用者の操作と実装上の制約の正本。期限・コマンド・プロセス管理を変更したときに更新する。検証画面とデータの使い方は[ローカル検証](local-verification.md)を参照する。

## 背景と目的

2026年10月4日のMac miniの発熱調査では、約3日残っていたNext.js開発サーバーがCPU約240〜420%、メモリ約9GBを使用していた。M4・メモリ16GBのMacで、対象を停止すると全体のCPU使用率が約11%、空きメモリが約6GBに改善した。メモリ増大の具体的な原因と温度そのものは未確定。

この変更の目的は、検証後に不要になったサーバーと子プロセスを終了し、並列開発に使うリソースを解放すること。処理を高速化する変更ではなく、停止漏れの継続時間に上限を設ける。メモリ増大の原因修正や、検証終了時の明示的な停止は引き続き必要になる。

## 起動コマンド

| 用途                    | 標準で2時間後に停止  | 期限なしの常駐                  |
| ----------------------- | -------------------- | ------------------------------- |
| Next.js                 | `npm run dev`        | `npm run dev:persistent`        |
| 通常開発用Worker        | `npm run dev:api`    | `npm run dev:api:persistent`    |
| Next.jsと検証専用Worker | `npm run dev:verify` | `npm run dev:verify:persistent` |

通常開発はNext.jsとWorkerを別の端末で起動する。各起動の期限も個別に管理する。`dev:verify` は一つの起動で両サービスを管理する。常駐用Workerでも通常と同じmigrationの準備処理を行う。

標準期限は管理プロセスの起動から2時間。その後の初期化やビルドの時間も含み、操作や通信が続いていても期限で停止する。npmのpreスクリプトは管理起動前のため期限に含めない。起動時に停止期限を表示する。常駐コマンドは時間による自動停止を行わないが、`Ctrl+C`や起動元の終了では停止する。Mac再起動後の自動起動とクラッシュ時の自動復旧は行わない。

起動時に期限を変える場合は、ミリ秒単位の正の整数を環境変数で指定する。例えば3時間で起動するには次を使う。

```sh
IDEA_BOOST_DEV_TTL_MS=10800000 npm run dev:verify
```

実行中の期限を延長する操作は初版に含めない。長時間の確認は最初から期限を指定するか常駐を選び、期限切れ後は必要な環境だけ再起動する。常駐コマンドではこの値を期限として適用しない。

## 停止する範囲

起動管理はリポジトリ内の[管理スクリプト](../../scripts/dev-server.mts)をnpmコマンドから呼び出す。このMacへの専用ツールのインストールは不要。同じリポジトリを使う開発者にも同じ既定動作が適用される。対応環境はmacOS・Linux・WSLで、Windowsネイティブでは説明付きで起動を拒否する。

| 対象                                                       | 扱い                                                 |
| ---------------------------------------------------------- | ---------------------------------------------------- |
| その起動で作った監視プロセス、サーバー、同じグループの子孫 | 期限・手動停止・異常終了時に清掃する。               |
| 別worktreeや別の端末から起動したサーバー                   | 別の起動として扱い、停止対象に含めない。             |
| 常駐指定の環境                                             | 時間制限を設けず、手動停止か起動元の終了まで動かす。 |
| 管理スクリプトを通さず直接起動したサーバー                 | 自動停止の対象に含めない。                           |
| Codexセッション、Orca IDE、ブラウザ、本番環境、検証データ  | この期限では停止・削除しない。                       |

既存のポート使用者を自動終了したり、プロセス名で全 `node` を終了したりしない。他のリポジトリにも自動適用しない。対象サーバーが自分の子孫を別のプロセスグループへ離脱させた場合、そのグループは管理対象外。検証スクリプトは管理起動時に離脱させず、Next.jsとWorkerを同じ清掃範囲に含める。

## 並行worktreeでの操作

ポートの自動配分は行わない。既存のポート指定を使い、別worktreeの環境と重ならないようにする。指定しない場合の3000・8787は従来どおり。

```sh
# 通常開発のNext.js。APIのURLはそのworktreeの環境設定と合わせる。
npm run dev -- --port 3001

# 通常開発用Worker。対応するNext.jsのAPI設定と合わせる。
npm run dev:api -- --port 8788

# 通常開発と分離された検証環境。両方のポートとURLをまとめて設定する。
IDEA_BOOST_VERIFY_APP_PORT=3001 IDEA_BOOST_VERIFY_API_PORT=8788 npm run dev:verify
```

利用者は通常どおり検証を依頼できる。後で自分が確認する場合は「確認用に残して、URLと期限を教えて」と伝える。継続利用する場合は「常駐で起動して」と明示する。常駐は停止期限がないため、使い終わったら起動元で `Ctrl+C` を押す。

期限切れ後に画面へ接続できなくなった場合は、端末の停止理由を確認し、再起動する。検証用環境は再起動でセッション秘密が変わるため再ログインが必要になる。保存済みの `.wrangler/verification/state` は削除しない。

## エージェントの指示

ユーザー共通の `~/.codex/AGENTS.md` には、必要な場合だけ起動する、自分が起動した一時サーバーを検証後に停止する、別セッションの環境を止めない、常駐指定を尊重する原則を置く。これは各ユーザーが設定する作業習慣で、リポジトリから変更しない。

このリポジトリの[AGENTS.md](../../AGENTS.md)は、この文書へ案内する。エージェントは標準コマンドを選び、検証終了時に期限を待たずに停止する。確認用に残す場合はURLと期限を伝え、停止回避のために勝手に常駐へ切り替えない。指示ファイル自体はタイマーを実行しない。

## プロセス管理と制約

起動元は、独立したプロセスグループの監視プロセスを起動し、IPCで接続する。監視側は実際のサーバーを同じグループで起動し、期限を判定する。起動元が強制終了すると監視側はIPC切断を受けて清掃する。監視側が先に終了すると起動元が残ったグループを清掃する。

通常の終了シグナルを送って猶予を与え、残ったプロセスは強制終了する。起動元が生存している場合はグループの消滅を確認する。起動元と監視側の両方を同時に強制終了した場合やOS異常終了まで保証する仕組みではない。管理状態をディスクに残して古いPIDを再利用する方式は採らない。

期限は日時で保持し、最大1秒間隔で再判定する。Macのスリープ中は処理せず、復帰後に期限切れなら停止する。OS時計を変更すると期限判定もその影響を受ける。2時間の停止は厳密な即時終了ではなく、期限検知と清掃の猶予を含む。

本番の起動・ビルド・Storybookの起動はこの変更の対象外。サーバー一覧、実行中の期限延長、負荷警告、複数リポジトリ向けの共通パッケージ化は初版に含めない。

## 検証

[プロセス管理テスト](../../scripts/dev-server.spec.ts)は短い試験用期限で、期限切れ、常駐の継続、手動停止、起動元と監視側それぞれの強制終了、TERMを無視する子孫の終了、他の起動の維持、既定2時間と不正な期限を確認する。既存の[検証起動テスト](../../scripts/verification.spec.ts)と[終了処理テスト](../../scripts/verification-process.spec.ts)も実行する。

実サーバーでは通常起動と検証用起動の準備完了、短い期限による停止、関連プロセスと待ち受けの消滅、常駐用の準備完了と手動停止を確認する。Macのスリープ・復帰は自動テストで代替せず、未実施ならPRに明記する。
