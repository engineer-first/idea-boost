# 作業を引き継ぐ

次の担当者が、承認済みの内容を再相談せず、今ある差分と残作業から再開できるようにする。
引き継ぎだけの依頼では実装やworktreeの削除を始めない。

## 現在の状態を確かめる

リポジトリルートで次を読み、会話の記憶と実ファイルを照合する。

```sh
git remote -v
git branch --show-current
git rev-parse HEAD
git status --short
git diff --stat
git diff --cached --stat
git ls-files --others --exclude-standard
```

PRがある場合は `gh pr view <番号> --json url,headRefOid,baseRefName,isDraft` も確認する。
「手元で実装済み」「commit済み」「push済み」を分け、PRに含まれない差分を明記する。
未追跡ファイルも用途を確認するが、秘密値・Cookie・生ログを引き継ぎ文書へコピーしない。
元のcheckoutや別の人の変更はそのまま保持する。

## 引き継ぎ文書と再開依頼文を作る

必要な項目だけを、次の順にまとめる。

1. **目的と完了条件**：利用者の困りごと、今回達成する状態、対象Issue/PR。
2. **決まったこと**：承認済み仕様と根拠。提案中・未確認の事項は分ける。
3. **依頼された操作範囲**：実装、commit、push、PR作成、merge、公開のどこまでか。過去の別作業の承認を今回へ持ち込まない。
4. **コードの所在**：作業ディレクトリ、ブランチ、base/head SHA、PRのhead、未commit・未pushのファイルと変更内容。
5. **検証**：red/greenのコマンドと結果、検証した版、その後に変えた箇所、失敗・未実施。画面資料は撮影した版とPRで見られるURLを対応させる。
6. **残作業と最初の一手**：既知の問題、判断待ち、次に読めばよいファイル、再現条件。
7. **動作中の環境**：自分が起動したサーバーのURL・期限・停止方法。別worktreeのサーバーと区別する。

保存先を指定されていなければ、`git rev-parse --git-path agent-handoffs` で得た
worktree固有のローカル領域に、日付と作業名を含むMarkdownとして保存する。
この文書自体はgit管理されない。チーム共有を依頼された場合は、依頼された共有先へ
確定事項と必要な資料を反映する。ローカルパスだけで他のPCでも読めるとは扱わない。

最後に、次の担当者へ渡せる短い依頼文と文書へのリンクを返す。
再開時は [AGENTS.md](../../../AGENTS.md) を読み、HEAD・作業差分・PRの最新状態を
取り直すよう案内する。元の個人用スキルやOrcaがなくても進められるよう、
承認済みの結論と必要な手順を残し、個人用スキル本文や作業ログは転載しない。
